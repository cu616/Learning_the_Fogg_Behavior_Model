# ADR-0034：工作流返回栈与状态树折叠

- 状态：已接受
- 日期：2026-08-23

## 背景

一次性行为的 MAP 诊断会根据回答进入不同页面，误点后缺少就地返回路径。长期行为同时存在多个黄金行为时，左侧永久展开所有微习惯方案会挤占大量空间。

## 决定

1. 一次性行为顶部增加会话级“返回上一个流程页面”按钮，保存最近 20 个页面快照，包括页面、因素、进入方式、线索和当前 P/A 回答。
2. 返回只恢复导航与表单视图，不回滚已经写入数据库的行为、诊断或日志。
3. 返回栈只在当前工作台会话有效；重新打开任务时仍以数据库保存的当前流程位置为准。
4. 长期设计状态栏把每个黄金行为作为可折叠节点；当前微习惯所属黄金行为自动展开，其他节点默认保持安静，节点标题显示方案数量。
5. 微习惯方案行降低高度和字号，仍保留名称与状态；当前方案继续用主题色定位。

## 理由

页面返回需要可逆但不能悄悄删除已保存记录。状态树使用渐进披露，可以在多个黄金行为下维持定位能力，同时避免左栏成为第二个主工作区。

## 影响

- 用户可从 MAP 分支直接返回，不必退出到首页。
- 左栏在大量黄金行为下显著缩短，但用户需要主动展开非当前分支。
- 会话返回不是数据撤销；按钮提示中明确说明保留已保存内容。

## 备选方案

### 使用浏览器历史

当前工作台是单页内部状态切换，浏览器历史无法可靠恢复因素和回答，拒绝。

### 永久折叠所有黄金行为

会隐藏正在设计的上下文，拒绝。
