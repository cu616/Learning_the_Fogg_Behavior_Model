# ADR-0033：当前行动中心与三类工作流统一首页

- 状态：已接受
- 日期：2026-08-23

## 背景

首页已经能够分类管理长期习惯、一次性行为和终止旧习惯，但三个分区默认收起后，用户打开软件时只能看见类别和数量，不能直接继续最近的设计、行动或观察。同一个状态筛选器在三类对象上的实际规则也不一致，搜索、归档和空结果容易产生误解。

这款产品的首要价值是帮助用户完成当前一个行为设计动作，而不是展示管理仪表盘或连续打卡统计。

## 决定

1. 首页第一阅读层改为“继续进行”，最多显示三个未归档对象，按最近更新时间排列。卡片直接说明对象类型、当前阶段和下一步，并可一步返回对应工作台。
2. “继续进行”只根据用户已有状态和最近更新时间排序，不评分、不生成连续天数、不推测意志力，也不将未继续描述为失败。
3. 三类分区继续作为管理层并默认收起，不替代长期习惯的七步主工作流。用户手动展开后，当前展开状态作为本机界面偏好保存，不进入行为数据导出。
4. 状态筛选和文本搜索对三类对象使用统一语义：“全部”默认不包含已归档，“归档”只显示已归档；设计中、实践中、稳定和暂停根据每类对象自身状态明确映射。
5. 搜索与筛选是管理工具，只影响三类分区的结果，不重排“继续进行”；清空搜索和重试加载必须有明确操作。
6. 首页、锁屏和主要全局操作使用同一套内联 SVG 图标，保留文字、`title`、`aria-label`和键盘焦点；不依赖符号字形、网络图标库或在线资源。
7. 加载、空结果、错误和正在执行的写操作必须在页内反馈；单个写操作不得因重复点击并发执行。

## 理由

- 让用户打开软件就能回到最近的真实行动，降低在三类项目中再次定位的成本。
- 将行动层和管理层分开，能保留 ADR-0019 的渐进披露，又避免收起后的首页只剩三个分类标题。
- 使用明确状态映射，可以避免同一筛选器对不同对象产生不同、不可预测的结果。
- 运行统计只用于定位，不用于奖惩，符合“帮助人们感受成功”和不以连续打卡驱动行为的约束。

## 影响

- `app/src/App.tsx` 需要拆分首页展示模型，增加加载、写操作和统一筛选状态。
- `app/src/uiPreferences.ts` 增加首页分区展开偏好，仅保存在本机 WebView。
- `app/src/components/UiIcon.tsx` 增加首页所需的内联图标。
- 首页 CSS 需要新增当前行动层、状态摘要、局部加载和窄窗口回退样式。
- 不改变 SQLite 结构、备份、导入导出、三类工作流和离线边界。

## 与现有决策的关系

- 补充 ADR-0019 的按需展开首页；三类管理分区默认收起的决定继续有效。
- 继续遵守 ADR-0001、ADR-0005 的本地优先与无网络核心路径。
- 继续遵守 ADR-0012、ADR-0020 的响应式排版、紧凑操作和无障碍名称。
- 继续遵守 ADR-0032 的深色材质与语义色锚点。

## 备选方案

### 默认展开全部三类项目

会重新制造首屏拥挤，项目增多后滚动成本很高，拒绝。

### 使用连续天数和完成率排序

会把产品推向打卡监督器，也容易让中断变成对用户的评判，拒绝。

### 为三类对象分别建立独立首页

能减少单页内容，但会增加跨工作流切换和搜索成本，当前个人本地工作台不需要此层导航，拒绝。
