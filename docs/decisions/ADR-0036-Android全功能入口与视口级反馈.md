# ADR-0036：Android 全功能入口与视口级反馈

- 状态：已接受
- 日期：2026-08-23
- 替代范围：扩展 ADR-0035 中“Android 仅呈现一次性行为”的阶段性限制
- 补充：ADR-0004、ADR-0024、ADR-0034、ADR-0035

## 背景

Android 一次性行为 Demo 已验证 Tauri 2、React、Rust、SQLite 和离线资源可以在真机竖屏环境运行。用户希望继续移植长期习惯设计和终止旧习惯，并保留当前移动版的单列、触控优先和 WeTab 启发视觉风格。

现有错误信息通常渲染在页面内容流的顶部。手机用户滚动到长表单下方后，即使操作失败，错误仍出现在文档顶部，当前视口无法看到，容易误以为按钮没有响应。

## 决定

1. Android 入口由“一次性行为 Demo”扩展为完整移动入口，呈现长期习惯设计、一次性行为、终止旧习惯和共用数据管理。
2. 三类移动工作流继续复用桌面端的 React 组件、Rust 命令、SQLite 表、配方版本、实践日志和诊断记录；不建立移动专用数据协议。
3. 移动首页提供三个互斥的行为类型入口。每次只展示当前类型的创建表单、筛选和项目列表，避免三类内容同时平铺。
4. 现有宽屏工作台增加移动显示模式：
   - 中央当前步骤仍是唯一主内容；
   - 状态栏和福格笔记改为按需覆盖层；
   - 步骤导航允许横向浏览，但每个操作目标保持不小于 48dp；
   - 长表单、卡片网格和底部操作在紧凑宽度下改为单列。
5. 所有操作级错误使用统一的视口级反馈层：固定在安全区下方、位于当前可视区域顶部、具有足够层级和关闭操作，并使用 `role="alert"`。它不随文档滚动离开视野，也不改变下面页面的排版位置。
6. 字段级校验仍可保留在字段附近；视口级错误用于保存、删除、加载、数据库命令等操作失败。错误文字应说明发生了什么，不把问题归咎于用户。
7. Android 版继续离线运行，不增加网络权限、在线字体、在线图片、账号或远程同步。

## 理由

- 复用现有领域实现可以让移动端立即获得完整的日志、版本和备份能力，并避免桌面与手机数据语义分叉。
- 单一移动首页中的类型切换比把三个大型模块同时铺开更易扫描，也符合渐进披露原则。
- 视口级错误能在长页面的任何滚动位置立即被看见，同时不会把页面推开或导致跳动。
- 状态和知识点继续按需覆盖，可以在窄屏保留中央任务的视觉主导地位。

## 影响

- `MobileApp` 负责三类项目的创建、列表、管理和工作台路由。
- `Workbench` 与 `OldHabitWorkbench` 增加可选的移动显示模式，桌面默认布局不变。
- 新增统一浮动错误组件和移动安全区样式；现有操作错误逐步接入该组件。
- Android 包体和数据库结构不因本决策新增网络依赖；Android 与 Windows 仍各自保存设备本地数据库。

## 备选方案

### 为三类行为分别编写原生页面

会复制大量工作流、验证和数据保存逻辑，维护成本高，暂不采用。

### 直接在 Android 渲染桌面首页

虽然开发量较小，但三类模块和宽屏侧栏会同时争夺窄屏空间，拒绝。

### 错误发生时自动滚动到页面顶部

会打断用户当前位置，也可能让键盘、表单上下文和未完成输入离开视野，拒绝。
