# ADR-0023：中性骨架与七步协调色谱

- 状态：已接受
- 日期：2026-08-22

## 背景

ADR-0022 用浅湖绿画布、雾白工作面和深青蓝操作色解决了纯白刺眼与表面层次不足的问题。但长期习惯工作流原本就用七种不同颜色帮助用户识别步骤：第一步紫色、第二步浅蓝、第三步深蓝，之后依次使用陶土、橄榄、赭黄和玫瑰色。当湖绿色同时承担窗口背景、全局操作、左侧轨道和多数图标时，步骤色会像临时插入的装饰；如果取消步骤色，七步又会失去快速定位并变得单调。

左侧“设计状态”还混用了当前页面颜色和全局湖绿。愿望、黄金行为、基线、锚点、庆祝实际来自不同设计步骤，但其颜色没有稳定语义，所以用户看到的是随机彩色图标，而不是可学习的状态结构。

## 决定

1. 将窗口骨架改为冷中性色：灰蓝画布、雾白工作面、中性灰蓝左栏和深蓝青全局操作色。全局色只服务首页、一次性行为和跨流程控制，不再主导七步中央工作区。
2. 七步采用一套同明度、同饱和度等级的协调色谱：紫、青蓝、深蓝、陶土、橄榄、赭黄、玫瑰。每种步骤色同时提供深色强调与浅色承托两个令牌。
3. 长期习惯工作台的当前步骤按钮、主要动作、输入焦点、标题标记和中央工作面顶部气氛都使用当前步骤色；色彩面积保持克制，主体文字与大面积表面继续使用中性色。
4. 顶部七步导航中的每个圆点保留自己的步骤色。已完成、当前和未开始状态仍通过填充强度、边框和文字共同表达，不能只靠颜色。
5. 左侧设计状态按“结果来自哪一步”着色：愿望对应第一步，黄金行为对应第三步，微习惯与基线对应第四步，锚点对应第五步，庆祝与完整配方对应第六步。状态轨道和栏背景保持中性，避免彩色区块相互争夺注意。
6. 所有深色步骤令牌与白色文字的对比度不低于 4.5:1。浅色令牌只作为背景，正文继续使用 `ink` 或对应深色令牌。
7. 颜色仅改变视觉层级，不改变数据结构、保存、日志、备份或离线运行方式，也不引入在线字体、远程样式或网络请求。

## 理由

- 中性骨架使七步颜色成为有含义的导航，而不是与全局绿色竞争的装饰。
- 同一色调等级比随意挑选七个颜色更协调，同时仍保留每一步的身份。
- 左侧按来源着色能让颜色承担“这个结果在哪一步形成”的信息，符合状态栏持续生长的产品逻辑。
- 用语义令牌区分中性、全局操作、步骤和状态来源，后续修改可以一次覆盖同类元素，减少颜色漂移。

## 影响

- 本决定调整 ADR-0022 第 6 条中的具体“湖绿工作面”方案；ADR-0022 关于非纯白背景、常驻设计状态栏和右侧按需抽屉的决定继续有效。
- `DESIGN.md` 与 `app/src/App.css` 需要同步新增七步色谱令牌和使用边界。
- 首页与一次性行为继续使用统一的全局操作色；长期七步工作台以内嵌步骤色为主。
- 不涉及数据库迁移，已有项目和实践日志完整保留。

## 备选方案

### 全部统一为湖绿色

未采用。视觉一致但失去七步定位感，长期使用会显得单调。

### 保留湖绿骨架并增强七步颜色

未采用。两套强色彩体系会继续竞争，步骤切换显得突兀。

### 为左栏每个图标自由选择颜色

未采用。丰富但不可学习，后续新增结果时也容易继续漂移。
