# ADR-0010：多黄金行为与渐进式设计工作台

- 状态：已接受
- 日期：2026-08-22

## 背景

当前 MVP 将一个习惯项目近似处理为“一项愿望、一项黄金行为、一套微习惯设计”。实际使用表明，这种结构不能充分表达书中的行为设计过程：一个愿望经过行为集群和焦点地图后，可能同时得到多个黄金行为；每个黄金行为还可能产生一个或多个微习惯方案，并需要各自进行提示匹配、庆祝、实践和迭代。

当前工作台右侧只显示通用提示，用户在进入后续步骤后不容易持续看见已经确定的愿望、黄金行为、基线和配方。第三步采用离散按钮评分，缺少焦点地图的空间操作；第四步要求一次显示并填写所有字段，增加了不必要的填写负担；第二步还会把附录中的完整微习惯配方直接添加为候选行为，使锚点在第五步之前提前混入流程。

参考原书：焦点地图见 PDF 第 88–94 页；能力链与 PAC 简化方式见 PDF 第 110–119 页；锚点与完整微习惯配方见 PDF 第 141–150 页。

## 决定

### 1. 工作台使用“渐进式设计摘要”

- 桌面宽屏下，左侧固定显示本项目已经确定的核心结果，中间显示当前步骤，右侧显示书中要点和操作帮助。
- 左侧摘要随步骤逐渐生长，而不是一次显示所有空字段：
  - 第一步完成后显示最终愿望；
  - 第三步显示所有已选择的黄金行为；
  - 第四步显示当前微习惯的基线行为与可选扩展；
  - 第五步显示选定锚点；
  - 第六步显示庆祝方式和完整配方；
  - 第七步显示当前实践分支及最近一次调整。
- 点击左侧黄金行为或微习惯分支，可以切换中间区域正在设计的对象。
- 窄窗口下左侧摘要和右侧帮助应可折叠，不能挤压核心表单。

### 2. 一个愿望可以拥有多个黄金行为

- 第三步不再强制项目只有一项活跃黄金行为。
- 用户可以从焦点地图右上区域选择多个黄金行为，也可以取消选择或暂存。
- 每个黄金行为拥有独立的后续设计上下文。
- 每个黄金行为可以拥有一个或多个“微习惯分支”；每个分支分别保存能力分析、微行为、锚点、庆祝、配方版本、实践日志和诊断记录。
- 不同分支可以独立处于设计中、实践中、稳定、暂停或归档状态。

概念关系为：

```text
愿望项目
  └─ 多个黄金行为
       └─ 一个或多个微习惯分支
            ├─ 能力分析与简化方案
            ├─ 锚点与庆祝
            ├─ 配方版本
            └─ 实践记录与诊断
```

### 3. 第二步改为行为集群画布

- 参考原书 PDF 第 81–83 页的图 2-6 和图 2-7，中央用云朵显示第一步确定的最终愿望，周围用独立行为卡片显示候选行为，并用箭头指向中央云朵。
- 每添加一个行为，就在云朵周围增加一张可以编辑、移动和删除的卡片；画布自动安排初始位置，同时允许用户拖动整理。
- 不把界面限制为书中示意图的 10 个框。行为较多时扩大画布、缩放或平移，继续支持发散。
- 画布强调“很好，还有呢？”的发散节奏。本步骤不显示影响、可行性或黄金行为判断，避免过早筛选。
- 列表或紧凑模式可作为无障碍与小窗口替代视图，但行为集群画布是桌面端主视图。

### 4. 第三步改为可拖动焦点地图

- 使用二维 9×9 焦点地图：纵轴为对愿望的影响程度，横轴为现实可行性。
- 每个候选行为显示为可拖动卡片；卡片可在画布中连续移动，九级刻度用作判断参照和键盘调整单位，而不是把卡片限制在九个离散点上。
- 持久化归一化坐标，并按需要映射成 1–9 的影响值和可行性值。
- 右上区域作为黄金行为候选区，用户仍需主动确认选择，不能仅凭坐标自动替用户决定。
- 支持多选黄金行为。
- 为键盘操作和精确调整保留非拖拽输入方式；拖拽不是唯一操作途径。

### 5. 第四步改为能力链与条件展开

- 用重新绘制的交互式能力链表达时间、资金、体力、脑力和日程五个环节，不直接嵌入 PDF 位图。
- 用户点击或选择最薄弱环节，并可补充“是什么让它难以做到”的说明；不再要求对每个环节机械打分。
- 简化方案按书中三个上位方向组织：提升技能、获取工具和资源、让行为变得微小。
- “让行为变得微小”下面再选择“入门步骤”或“缩小规模”，两者是并列的微小化方法。
- 只有用户选中的简化方向才展开相应字段：
  - 提升技能：需要提升的技能、准备怎样学习或练习；
  - 工具和资源：需要的工具、资源或帮助；
  - 入门步骤：原行为与第一个小动作；
  - 缩小规模：原行为与缩小后的微行为。
- 基线行为和可选扩展始终显示，并同步进入左侧摘要。
- 同一黄金行为下的不同微习惯分支分别保存上述内容。

### 6. 第二步只探索候选行为，不提前确定锚点

- 第二步的主要产物只能是可观察、可执行的候选行为，不是完整配方。
- 附录中的 300 条完整微习惯配方仍可作为灵感参考，但在第二步选用时，软件必须让用户提取或确认其中的“新行为”部分，不能把整条“在……之后，我会……”字符串直接保存为行为选项。
- 配方中的锚点部分可以作为来源信息暂存，但只有在第五步经过地点、频率、主题和最后动作匹配后，才能成为该微习惯分支的正式锚点。
- 完整配方只在第五步完成锚点匹配后组装，并在第六步加入庆祝后进入实践。

### 7. 第七步增加实践感受

- 每次实践记录除结果类型外，还可以填写自由文本感受。
- 感受文本可记录当时情境、身体感受、阻力、惊喜或对配方的想法，不要求用户写满，也不作为成功判定条件。
- 现有 `practice_event.notes` 字段继续承载该信息，无须仅为此增加新表。
- 历史列表应显示感受摘要，并允许查看完整内容。

### 8. 第一步只要求确认最终愿望

- 用户进入第一步时，主区域只突出一个需要完成的核心任务：写下并确认最终愿望。
- 不再把“这对你为什么重要？”和“如果改变，生活会有什么不同？”分别显示为两个常驻输入框。
- 在最终愿望下方提供可折叠的“帮助我想一想（非必填）”区域；两道问题作为思考提示，共用一个可选的思考记录区。
- 可选思考记录不作为步骤完成条件，留空不会出现警告或未完成状态。
- 初始表达与最终愿望不再要求用户在两个外观相同的常驻文本框中重复填写。用户第一眼只看到最终愿望字段；如果系统判断输入更像成果或具体行为，只显示可忽略的改写提示。
- 迁移时可以保留旧的原始输入和两个引导回答，但新界面不强迫用户逐项维护。

## 理由

- 与书中允许从一个愿望筛出多个黄金行为的焦点地图过程一致。
- 让用户始终看得见自己已经作出的关键设计决定，减少跨步骤记忆负担。
- 用空间操作还原焦点地图的比较过程，比孤立的 1–5 按钮更容易形成整体判断。
- 条件展开只呈现当前选择所需的字段，降低表单负担。
- 清楚区分候选行为、微行为、锚点和完整配方，避免步骤二与步骤五职责重叠。
- 实践感受为后续诊断和配方迭代提供比结果标签更丰富的上下文。

## 影响

- 当前数据库以 `project_id` 直接关联能力分析、微行为、锚点、庆祝、配方和实践记录，无法完整表达多黄金行为和多微习惯分支，需要新增分支实体并迁移外键。
- `golden_behavior` 的“单一活跃项”后端逻辑和前端选择逻辑必须改为多选。
- 导出格式、导入 ID 映射、备份恢复和测试数据都要覆盖新增关系；如导出格式不再向后兼容，应新增格式版本或迁移规则。
- 工作台由当前两栏改为桌面三栏，并需要响应式折叠行为。
- 第二步需要行为集群画布、动态布局、连线、缩放/平移和替代列表视图。
- 第三步需要拖拽、连续坐标持久化、九级键盘调整及碰撞/重叠处理。
- 现有附录配方 JSON 只有完整文本。实现“提取新行为”时应优先增加经过校验的结构化派生数据或明确的人工确认步骤，不能依赖不透明的在线 AI。
- 第七步感受文本已有数据库字段，属于低风险的前端增量，可以先于其他结构迁移实施。

## 与现有决策的关系

- 细化 ADR-0002，不改变七步行为设计作为主工作流的决定。
- 继续遵守 ADR-0001 的本地优先和离线可用要求。
- 继续遵守 ADR-0005：焦点地图、能力链和配方拆分的核心功能不能依赖在线 AI。
- 不改变 ADR-0009 的一次性任务补充工作流；本 ADR 针对长期习惯设计。

## 未采用方案

### 继续限制每个项目只有一个黄金行为

未采用，因为书中的焦点地图可能同时得到多个黄金行为，也不符合用户围绕一个愿望培养多项行为的实际需要。

### 将完整附录配方直接加入第二步

未采用，因为它提前确定了锚点，削弱了第五步的匹配与试验过程。

### 始终展示第四步全部字段

未采用，因为未使用的简化方法不应制造填写义务。

### 将第一步的两道引导问题作为独立必填项

未采用。它们适合帮助思考，但不应让用户刚进入流程就面对多个必须填写的空框。

### 直接使用 PDF 中的能力链图片作为交互界面

未采用。软件将重新绘制表达相同方法的交互式图形，以便响应用户操作、适配窗口和保持界面一致性。
