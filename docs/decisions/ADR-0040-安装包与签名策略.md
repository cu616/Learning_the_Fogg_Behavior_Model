# ADR-0040：安装包与签名策略

- 状态：已接受；远程镜像范围由 [ADR-0041](./ADR-0041-独立动漫分支与Fork完整镜像.md) 补充
- 日期：2026-08-24
- 关联：[ADR-0035](./ADR-0035-动漫IP视觉主题与可替换资产层.md)、[ADR-0039](./ADR-0039-Android构建与移动端边界.md)

## 背景

项目同时生成 Windows 便携程序、Windows 安装程序和 Android APK。Windows 可执行文件目前没有商业代码签名证书，Android 第一阶段使用调试签名，因此需要明确各产物的安装方式、系统提示和后续升级路径。

## 决定

1. Windows、Android 与源码仓库使用同一产品名称和版本记录，不增加额外的内部分类标签。
2. Windows 同时提供便携 `app.exe` 与 NSIS `Setup.exe`。便携版可直接运行；安装版负责快捷方式、卸载入口与运行时安装检查，更适合普通测试用户。
3. 没有可信代码签名证书时，Windows 安装程序必须说明可能出现“未知发布者”或 SmartScreen 提示，不把未签名包描述为正式可信发布版。
4. Android 第一阶段继续生成 ARM64 调试签名 APK，只供设备兼容性和交互测试。面向长期分发前，另行建立由用户自己保管的发布密钥，并记录包名、密钥备份和升级策略。
5. Windows 与 Android 数据各自保存在设备本地，不自动同步。第三方测试者的数据不得通过开发者服务收集。

## 理由

- Setup 改善的是安装和卸载体验，并不自动解决软件签名。
- Android 调试签名可以尽快验证真机，但调试密钥不应成为长期分发身份。
- 把安装方式和签名状态写清楚，可以让后续升级保持一致。

## 影响

- 当前生成的 Setup、便携版和 APK 使用统一产品名称与版本号。
- 若希望减少系统安全警告，需要准备 Windows 代码签名证书和 Android 发布密钥。
- Android 发布密钥一旦用于对外版本，后续更新必须持续使用同一密钥；密钥和密码不得提交到仓库。

## 备选方案

### 直接把当前包公开发送

无法解决 Windows 未签名提示和 Android 调试签名的升级问题，不采用。

### 只发送便携 EXE

技术上可行，但普通用户缺少快捷方式、卸载入口和运行时提示。保留便携版作为高级用户选项，同时提供 Setup。

### 立即创建正式签名密钥

Windows 证书需要用户选择可信证书来源，Android 密钥需要由用户长期保管密码和备份。当前没有足够的密钥管理信息，暂不擅自创建。
