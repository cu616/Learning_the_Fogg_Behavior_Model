# ADR-0015：可恢复删除与画布可视化语义

- 状态：已接受
- 日期：2026-08-22

## 背景

首页只有归档，没有真正删除入口；第二步行为卡片固定大小，短行为留下过多空白，长行为又难以阅读；第三步虽然采用九级判断，却显示为 1～9，缺少以 0 为中心的四象限感。应用整体还过度依赖同一种蓝色和长段文字来表达层级。

## 决定

1. 长期行为设计和一次性行为都提供“永久删除”操作。界面在执行前显示对象名称并要求再次确认；后端在级联删除前自动创建完整 SQLite 保护快照并登记到备份列表，用户可从数据管理恢复。
2. 第二步行为卡片保存宽度和高度。新卡片按文字长度给出紧凑默认尺寸，用户可拖动右下角控制柄自由调整；位置和尺寸都写入本地数据库。
3. 焦点地图继续保存九级精度，但对用户使用 `-4～4` 的中心化坐标语义。横轴为可行性，纵轴为影响；0 对应两条明显的中心轴，右上方的正向区域用于比较黄金行为候选。
4. 七步使用各自的克制主题色和线性符号图标；图标只用于步骤标题、主要引导和区域识别，保留文字标签与无障碍名称，不以图标替代关键信息。
5. 不引入网络字体、外部图标服务或新的运行依赖，所有视觉资源随应用离线提供。

## 理由

- 自动保护快照在满足删除需求的同时降低误删后不可恢复的风险。
- 自由尺寸比按固定字数自动裁切更能适应用户自己输入的行为描述。
- `-4～4` 让 0 成为真正的判断中点，更符合四象限地图的直觉。
- 少量符号、分区色彩和更强层级可以减少大段文字造成的视觉疲劳，又不会把行为设计变成花哨的游戏界面。

## 影响

- 数据库升级到 schema v5；`behavior_option_layout` 增加 `swarm_width`、`swarm_height`。
- 行为布局 API 增加尺寸字段；焦点评分 API 在界面层与存储层之间进行 `-4～4` / `1～9` 映射，以兼容已有数据和约束。
- 删除会生成额外备份文件，仍由现有备份界面管理。

## 未采用方案

### 只提供归档

未采用。归档适合暂时隐藏，但不能代替用户明确要求的数据删除。

### 删除前不做保护快照

未采用。长期设计包含多个分支和实践历史，误删代价过高。

### 引入在线图标库

未采用。它会增加依赖并破坏核心离线保证；本轮简单符号已足够建立视觉层级。
