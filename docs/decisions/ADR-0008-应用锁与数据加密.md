# ADR-0008：应用锁与数据加密

- 状态：已接受
- 日期：2026-08-21

## 背景

软件保存愿望、行为、情绪感受与日常实践等个人敏感数据。虽然本地优先、不上传，仍需防止他人（如共用电脑的人）随手翻看。

## 决定

- 首版实现**应用锁**：用户可设置密码（任意非空字符串），密码经 SHA-256 加盐哈希后存入 `settings` 表，不存明文。
- 启动时若已设密码则进入锁屏，验证通过后才显示主界面。
- **数据库整体加密（SQLCipher）暂不引入**，作为后续可选决策。

## 理由

- 应用锁以极低成本覆盖"防止他人随手查看"的主要隐私场景。
- SQLCipher 会显著增加构建复杂度、体积与性能开销，且对本地单用户威胁模型收益有限。

## 影响

- 密码可设置、修改、清除；验证失败不进入应用。
- 明文密码从不落盘，仅存加盐哈希。

## 未采用方案

- 数据库加密（SQLCipher）：收益/成本不划算，首版不做。
- 依赖系统账号锁（Windows Hello）：引入额外平台耦合，放弃。
