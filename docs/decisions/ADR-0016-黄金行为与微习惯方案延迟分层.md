# ADR-0016：黄金行为与微习惯方案延迟分层

- 状态：已接受
- 日期：2026-08-22

## 背景

第三步选择黄金行为后，旧实现立即用黄金行为文本创建同名微习惯分支。左侧摘要因此同时显示“AAA”黄金行为和“AAA”子分支，虽然数据层分别代表行为选择与后续配方方案，界面上却像重复信息，也在用户尚未进入第四步时过早创建了后续设计对象。

## 决定

1. 第三步选择新的黄金行为时只保存黄金行为，不再自动创建微习惯分支。
2. 用户首次进入第四步或更后步骤时，才为尚无方案的每个黄金行为创建一个分支，默认名称为“微习惯方案 1”。
3. 默认方案名称不复用黄金行为文本；左侧用父子层级、图标和缩进分别表达黄金行为与微习惯方案。
4. 微习惯方案可以直接重命名；新增同一黄金行为下的其他方案时使用“微习惯方案 2、3……”作为建议名。
5. 已经有方案的旧项目不迁移或强制改名，避免覆盖用户已有命名；用户可自行使用重命名入口调整。
6. 焦点地图把整个第一象限定义为候选区，即影响和可行性都大于 0；0 轴的正方向显示箭头，方向文字贴近对应坐标轴。

## 理由

- 数据对象在真正需要时才出现，符合渐进披露原则。
- 通用方案名能清楚表明它是黄金行为下面的一套微习惯设计，而不是第二个相同行为。
- 保留旧方案名称可以避免静默修改用户数据。
- 完整第一象限和轴向箭头更符合坐标图的视觉惯例。

## 影响

- 黄金行为选择命令不再为新选择插入 `habit_branch`。
- 工作台跨入第四步时执行一次幂等的分支补全；多黄金行为会各自得到第一套方案。
- 左侧摘要增加方案重命名入口和“第四步再设计”的空状态。

## 未采用方案

### 继续自动创建同名分支

未采用。它使两个数据层级无法从标题上区分，并提前暴露尚未开始的设计。

### 永远不创建分支，第四步直接写在黄金行为上

未采用。同一黄金行为仍可能需要多套不同微习惯方案，必须保留分支层级。
