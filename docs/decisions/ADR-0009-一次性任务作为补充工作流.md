# ADR-0009：一次性任务作为七步习惯设计的补充工作流

- 状态：已接受
- 日期：2026-08-22
- 后续实现：数据实体与当前版本范围见 [ADR-0014](ADR-0014-一次性行为独立实体与循环诊断.md)。

## 背景

现有产品以七步行为设计为主工作流，重点支持长期微习惯的设计、实践、诊断和生长。书中的福格行为模型并不限于习惯，也适用于一次性行为；入门步骤和情境提示也能帮助用户完成已经明确、但迟迟没有执行的单次任务。

如果直接把完整七步习惯流程套到每个一次性任务上，用户需要填写愿望、行为集群、焦点地图、长期锚点和实践记录，负担与任务价值不匹配。反过来，如果把一次性任务做成普通待办清单，又会丢失 `B = MAP`、能力链、入门步骤和无评判诊断等项目核心方法。

## 决定

- 保持 ADR-0002 确立的七步习惯设计为软件主工作流。
- 将“一次性任务快速流程”记录为未来补充工作流，用于明确且只需完成一次的行为。
- 一次性任务流程复用以下核心方法：
  - 将成果改写为具体的下一动作；
  - 按提示→能力→动机进行 `B = MAP` 诊断；
  - 使用能力链和“容易做”分析；
  - 通过缩小规模或入门步骤降低行动门槛；
  - 优先使用适时的情境提示；
  - 完成入门步骤或任务后立即创造积极情绪；
  - 未执行时修改设计，不评价用户人格。
- 一次性任务完成后关闭；只有当行为确实需要长期重复时，才转入七步习惯设计。
- 本决策接受工作流方向和文档化，不把该功能自动加入当前 MVP；具体版本范围仍需后续确认。
- 本决策不确定数据表结构和操作系统通知实现。实施前必须分别核对现有数据模型，并对重大变更建立或更新 ADR。

详细流程见：`docs/blueprints/一次性任务工作流.md`。

## 理由

- 忠实使用书中适用于单次行为的通用模型和方法；
- 避免为简单任务强制执行完整的长期习惯流程；
- 比普通待办清单更能解释并降低“知道要做但没有行动”的阻力；
- 保持提示→能力→动机的诊断顺序和无评判产品语气；
- 与本地优先、离线可用和不依赖 AI 的既有决定兼容。

## 影响

- 未来产品可能需要在“新建习惯设计”和“新建一次性任务”之间提供入口选择。
- 可以复用能力链、提示设计、庆祝方式和障碍诊断组件，但需要更轻量的交互。
- 一次性任务不默认创建长期实践日志、连续记录或扩展阶段。
- 首页将来可能需要同时呈现习惯项目和一次性任务，但不应把软件退化为普通任务清单。
- 数据模型可能需要泛化项目类型或增加独立实体，此事不由本 ADR 决定。
- 系统通知和提醒会影响隐私、权限和用户体验，需要单独决策。

## 与现有决策的关系

- 补充 ADR-0002，不替代七步行为设计主工作流。
- 继续遵守 ADR-0001 的本地优先与离线核心路径。
- 首次实现仍应遵守 ADR-0005，使用规则和本地知识，不依赖 AI。
- 任何数据模型、提醒策略和 MVP 范围的重大变化继续遵守 ADR-0003。

## 未采用方案

### 对每个一次性任务强制运行完整七步骤

未采用。流程负担过高，且长期锚点、重复实践和习惯生长并非单次任务的必要条件。

### 只增加普通待办清单

未采用。它无法利用 `B = MAP`、能力链和入门步骤来诊断、降低行为阻力，也与产品定位不符。

### 将一次性任务立即纳入当前 MVP

未采用。当前请求是为未来开发保存工作流；在没有完成数据模型、提醒策略和版本范围决策前，不扩大现有 MVP。
