# ADR-0039：原书与生成知识库纳入仓库

- 状态：已接受
- 日期：2026-08-24
- 替代：仓库早期“原始 PDF 与生成全文仅在本地保存”的约定

## 背景

项目最初只把提取脚本、精炼笔记和结构化参考库提交到 Git，原始 PDF、整本 Markdown、分章文件和页级索引被 `.gitignore` 排除。这样可以保持仓库较小，但新用户克隆后无法立即阅读原书、按章节学习或使用页级索引，必须自行准备文件并重新运行提取脚本。

仓库所有者已确认拥有把当前电子书及其生成内容上传、存储并提供给仓库用户学习的相应授权。当前 PDF 约 9.8 MiB，全部原书与生成文件合计约 11.5 MiB，低于 GitHub 普通 Git 的单文件限制，无需 Git LFS。

## 决定

1. 将授权的原始 PDF 以简洁稳定的路径 `source/福格行为模型.pdf` 纳入仓库。
2. 将以下生成内容一并纳入仓库：
   - `knowledge/福格行为模型-全文.md`；
   - `knowledge/chapters/` 全部分章 Markdown；
   - `knowledge/page-index.jsonl`。
3. 克隆仓库后即可直接阅读 PDF、全文、分章资料、理论笔记和结构化参考库，不再把重新提取作为开始学习的前置条件。
4. 生成文件仍不得手工批量改写。原书或提取规则变化时，运行 `scripts/extract_fogg_book.py`，并将 PDF、全文、分章和页级索引作为同一组变更提交。
5. README 明确软件提示只是精炼入口，概念不清楚时应阅读仓库中的 PDF、Markdown 全文、分章资料和笔记。
6. 版权与使用授权由仓库所有者负责维护。若未来授权状态改变，应立即停止分发相关文件，并通过新的 ADR 记录处理方式。
7. 原书与知识资料可以上传 GitHub，但个人习惯、实践日志、数据库、备份、应用锁信息及自定义背景仍不得默认上传；本决定不改变软件的本地优先隐私边界。

## 理由

- 用户克隆后即可学习和检索，不会因缺少原始资料得到残缺项目。
- 稳定、简短的 PDF 路径便于 Markdown、JSONL、脚本和后续 Agent 引用。
- 文件体积较小，普通 Git 能直接提供完整克隆体验，使用 Git LFS 反而会增加额外客户端和配额依赖。
- 原书、生成内容与提取脚本共同版本化，能够明确某一版索引对应哪一版来源。

## 影响

- `.gitignore` 不再排除 `source/` 与三类生成知识文件。
- Git 仓库体积增加约 11.5 MiB。
- 根 README、知识库 README、文档索引、工作日志和 Agent 协作说明同步更新。
- GitHub 仓库继续保持私有；未来若要改为公开仓库，必须重新核对原书分发授权与所有第三方资源许可。

## 备选方案

### 只上传提取脚本

会延续克隆后资料不完整的问题，不采用。

### 只上传 PDF，不上传生成内容

用户仍需配置 Python 依赖并重新提取，AI Agent 也不能立即进行分章检索，不采用。

### 使用 Git LFS

当前最大文件远低于普通 Git 单文件限制，引入 LFS 会增加克隆步骤和外部配额依赖，暂不采用。
