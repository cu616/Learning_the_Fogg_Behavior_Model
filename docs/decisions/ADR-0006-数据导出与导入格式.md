# ADR-0006：数据导出与导入格式

- 状态：已接受
- 日期：2026-08-21
- 后续更新：当前格式版本与兼容策略见 [ADR-0013](ADR-0013-导出格式升级与向后兼容.md)。

## 背景

软件需要支持数据的备份、导出、导入与跨设备迁移。本地优先原则要求数据可迁移、可验证、采用开放格式。MVP 已实现 JSON 导出，但缺少导入，导致"导出→迁移"闭环不完整。

## 决定

- 导出采用 JSON，格式标记为 `fogg-lab-export-v1`，包含 `exportedAt` 与 `tables`（14 张业务表的完整行）。
- 导入采用 `import_json`：按 `uuid` 在**项目级**去重（已存在的项目整体跳过）；对外键 `id` 做重映射（旧 id → 新 id，以 `uuid` 为稳定身份）；在事务内执行，全部成功或全部回滚。
- 表按依赖顺序导入：`habit_project` → 其余业务表（`focus_placement` 通过 `behavior_option_id` 关联）。

## 理由

- JSON 开放、可读、可验证，符合"优先使用可迁移、可验证的开放格式"。
- `uuid` 作为稳定身份，避免跨设备 INTEGER 主键冲突。
- 项目级去重覆盖最主流的迁移场景（把别处导出的项目合并进本机）。

## 影响

- 导入跳过 uuid 已存在的项目，暂不支持同一项目内的增量合并或冲突解决（后续需要时另立 ADR）。
- 导入结果只返回新增项目数，前端据此反馈用户。

## 未采用方案

- 二进制快照作为唯一导出格式：不可读、不可验证，放弃。
- 按行级 uuid 去重：可实现增量合并，但复杂度和风险更高，首版不做。
