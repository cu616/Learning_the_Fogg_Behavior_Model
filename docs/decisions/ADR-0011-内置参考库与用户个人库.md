# ADR-0011：内置参考库与用户个人库

- 状态：已接受
- 日期：2026-08-22

## 背景

软件目前随安装包提供微习惯配方库、庆祝方式库、肯定成功方式库和锚点模板。它们适合用来启发用户，但目前只能读取，用户在实践中发现的有效行为、锚点、庆祝方式和配方无法沉淀成自己的长期资源。

如果把用户每次输入的内容全部自动加入参考库，个人库会迅速积累重复项、临时草稿和无意保存的内容；如果要求用户离开七步流程进入单独管理页，又会增加保存成本。

## 决定

### 1. 区分内置库和“我的库”

- 内置库继续随软件离线提供，默认为只读，不因用户编辑而改变原始资料。
- 新增完全本地的“我的库”，用户可以新增、编辑、删除、分类和搜索自己的条目。
- 浏览参考资料时提供“内置”和“我的”切换，也可以合并搜索并标明来源。
- 用户可以把内置条目复制到“我的库”后再修改，不能直接覆盖内置内容。

### 2. 支持多种条目类型

首批个人库支持：

- 候选行为灵感；
- 完整微习惯配方；
- 锚点模板；
- 庆祝方式；
- 肯定成功的语言；
- 后续经 ADR 接受的其他参考类型。

不同类型保存适合自己的结构化字段。完整配方应尽量分别保存锚点、微行为和庆祝，而不只保存一整段无法拆分的文本。

### 3. 在七步流程中顺手保存

- 新增或编辑行为、锚点、庆祝和配方时，提供轻量的“同时保存到我的库”复选项或收藏按钮。
- 默认不自动保存，避免把草稿和一次性内容全部堆入个人库。
- 保存项目数据与保存到个人库是两个独立动作；未勾选个人库不影响当前项目保存。
- 已经保存到个人库的条目显示明确状态，重复保存时提醒用户选择复用、更新或仍然创建副本。

### 4. 本地存储、备份和迁移

- 个人库使用 SQLite 保存，核心操作完全离线，不发送到外部服务。
- 新增 `personal_reference_item` 概念实体，至少保存 UUID、类型、名称/正文、结构化内容、分类、标签、来源、创建时间和更新时间。
- 个人库纳入完整备份和全量 JSON 导出。
- 项目导出默认只携带项目实际使用的内容快照，不自动导出整个个人库；全量导出可以包含个人库。
- 从其他设备导入时按 UUID 去重，并允许在内容冲突时保留双方版本。

### 5. 与步骤职责保持一致

- 第二步个人行为库提供候选行为，不把锚点提前写入正式设计。
- 第五步个人锚点库提供锚点候选，仍需针对当前微行为进行地点、频率、主题和最后动作匹配。
- 第六步个人庆祝与肯定方式库提供候选，仍需由用户确认是否自然、是否能带来成功感。
- 个人完整配方库主要用于复用成熟设计；应用到新愿望时必须拆开确认行为、锚点和庆祝，不能跳过七步判断。

## 理由

- 用户能够积累经过自身验证、比通用示例更适合自己的设计资源。
- 在当前填写位置顺手保存，比要求跳转到独立管理页面更自然。
- 明确区分内置与个人内容，既保护书中参考资料，也避免用户误以为修改了原始库。
- 显式保存比全自动收集更容易保持个人库质量和用户控制感。
- 结构化配方可以在不同步骤分别复用，同时避免第二步与第五步职责混乱。

## 影响

- 需要新增数据库迁移、Rust CRUD 命令、TypeScript API 和个人库管理界面。
- 备份、全量导入导出和数据格式测试要覆盖个人库。
- 各步骤的添加控件需要提供统一的收藏/保存交互。
- 内置 JSON 与个人 SQLite 数据需要统一成前端可搜索的视图模型，同时保留来源标识。
- 删除个人条目不能破坏已有项目；项目应保存使用时的内容快照或稳定引用与回退快照。

## 与现有决策的关系

- 遵守 ADR-0001 的本地优先要求。
- 遵守 ADR-0005，个人库核心能力不依赖 AI 或网络。
- 补充 ADR-0010 中第二步参考库的职责划分。
- 实现时需与 ADR-0006 的导入导出格式建立兼容或版本升级方案。

## 未采用方案

### 自动保存所有输入

未采用，因为会收集大量草稿、重复内容和用户并不想长期保留的信息。

### 允许直接修改内置资料

未采用，因为升级时难以区分软件更新与用户编辑，也会破坏原始参考库的一致性。

### 只建立一个无类型的文本收藏夹

未采用，因为行为、锚点、庆祝和完整配方在七步流程中的职责不同，需要不同字段和应用规则。
