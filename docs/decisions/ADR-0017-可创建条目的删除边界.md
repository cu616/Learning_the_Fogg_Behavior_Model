# ADR-0017：可创建条目的删除边界

- 状态：已接受
- 日期：2026-08-22

## 背景

首页项目已经提供永久删除，但微习惯方案、锚点候选、庆祝候选，以及步骤内展开的个人参考库条目缺少一致的删除入口。用户会因此无法清理误建、重复或不再适用的卡片。同时，实践日志、诊断历史和配方版本承担回溯职责，不应与普通候选项采用相同的随手删除规则。

删除项目前创建保护快照的实现还曾把 `before-delete` 写入只允许 `full` 或 `project` 的 `backup_type`，导致数据库约束错误并阻止删除。

## 决定

1. 删除保护快照继续使用 `before-delete-*.db` 文件名和明确的内容摘要，但数据库记录类型使用合法的 `full`，表示它是完整数据库快照。
2. 用户直接创建、选择或收藏的可管理条目均提供删除或移除入口：行为候选、黄金行为选择、微习惯方案、锚点候选、庆祝候选、个人参考库条目和本地备份。
3. 删除微习惯方案会级联删除该方案下的能力分析、微行为、锚点、庆祝、配方版本、实践与诊断记录，因此必须二次确认，并在后端先创建完整保护快照。
4. 删除锚点候选或庆祝候选只删除当前方案中的候选记录；已经生成的历史配方保留当时的文字快照。
5. 步骤内“我的库”与数据管理页使用同一套个人库删除命令；删除个人库条目不影响项目里已经使用或复制的内容。
6. 配方版本、实践日志和诊断历史继续作为审计与复盘记录展示，不提供普通卡片式单条删除。需要清除整个实验记录时，通过删除其微习惯方案或行为设计项目完成，并依靠保护快照恢复。
7. 删除本地备份时同时删除数据库记录和对应快照文件；后端必须确认规范化后的文件路径位于应用自己的备份目录内，不能删除目录外的路径。

## 理由

- 可编辑集合应允许用户修正误操作和清理重复内容。
- 对含有历史记录的分支使用保护快照，可以在提供永久删除的同时降低误删风险。
- 保留历史配方和实践记录的完整性，有助于复盘设计变化，也避免删除一个候选项后破坏旧记录。
- `full` 准确符合现有数据库约束和快照实际内容，无需为了显示原因新增数据库枚举值。

## 影响

- 新增微习惯方案、锚点候选、庆祝候选和本地备份的后端删除命令与前端入口。
- 第二、第五、第六步中的个人库列表增加删除按钮。
- 第三步已选黄金行为摘要增加“移除选择”，其行为等同于在地图卡片上取消选择，不物理删除候选行为。
- 数据库 schema 不变。

## 未采用方案

### 为 `backup_type` 新增 `before-delete`

未采用。该文件仍是完整数据库快照，使用 `full` 更符合既有模型；删除原因已经保存在内容摘要和文件名中。

### 所有历史记录都提供单条删除

未采用。配方版本、实践和诊断是彼此关联的回溯记录，零散删除会损害实验历史的可理解性。
