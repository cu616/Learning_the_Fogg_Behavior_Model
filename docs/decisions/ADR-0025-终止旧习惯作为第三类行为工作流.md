# ADR-0025：终止旧习惯作为第三类行为工作流

- 状态：已接受
- 日期：2026-08-22

## 背景

产品已经分别支持需要长期重复发生的“长期习惯设计”和只需这一次发生的“一次性行为”。用户还需要处理第三类目标：让一个已经反复发生的旧行为减少、停止，或用更合适的新行为替代它。

书中的行为改变系统方案仍以 `B = MAP` 为基础，但方向与前两类不同：优先移除、规避或忽略旧提示；其次让旧行为更难做到；最后才谨慎调整动机。措施需要在多个真实情境中持续观察，不能用一次完成或连续打卡作为结束条件。

详细产品流程见 `docs/blueprints/终止旧习惯工作流.md`。

## 决定

1. 将“终止旧习惯”确立为与长期习惯设计、一次性行为并列的第三类正式工作流。首页使用第三个可折叠分区，说明其适用于“减少、停止或替代重复行为”。
2. 终止旧习惯使用独立实体，不向长期习惯或一次性任务表追加大量可空字段。顶层旧习惯项目包含多个具体旧行为；对策、观察和替代方案分别保存历史。
3. 工作流包含三个阶段：
   - 阶段 1：可选的改变准备。用户可以跳过、关联已有长期习惯，或自由填写自己已有的改变经验；也可以从这里新建长期习惯。
   - 阶段 2：把概括型旧习惯拆成具体行为，一次聚焦一个最容易处理的行为；完整呈现 P/A/M 对策地图，完成首次布置并进入持续观察。
   - 阶段 3：需要时用新行为替代旧行为。用户可以在当前项目内填写替代方案，也可以直接创建并关联一个新的长期习惯项目。
4. P/A/M 工作台完整显示 3 个提示方向、5 个能力方向和 2 个动机方向的标题及已有内容，但一次只展开一个编辑区。任何区域均可为空；首次设置允许同时采用多项安全、低成本、可恢复的环境措施。
5. 每个具体旧行为采用统一的目标模型：完全停止、减少次数、缩短时长、降低强度或有限周期实验。目标是否达到由用户确认，软件不使用连续天数自动宣布永久戒除。
6. 观察记录保留“没有发生、减少、再次发生、未遇到情境、暂不记录细节”等无评判结果。再次发生表示获得了新的设计信息，不设置“失败”状态或清零机制。
7. 自由落体型行为不通过关键词自动诊断或硬性阻止。界面提供按需展开的专业支持边界，明确严重成瘾、进食障碍、自伤等情况不应只依赖本软件。
8. 界面继续遵守现有设计语言：冷灰蓝中性骨架、首页自适应卡片网格、左侧常驻行为状态、中央唯一主任务、右侧按需理论抽屉、简短标签、语义化双列和渐进披露。右侧笔记不显示章节编号。
9. 核心流程、理论笔记、保存、观察、备份及导入导出完全离线。第三类工作流数据纳入完整 SQLite 备份和全量 JSON 导入导出；导出格式升级并继续兼容旧文件。

## 理由

- 独立生命周期能表达跨情境观察、多个具体旧行为和逐步加固的防线，不会把一次性任务的结束语义强加给旧习惯。
- 完整地图与局部编辑兼顾书中方法的完整性和页面注意力，避免一次出现十组空表单。
- 允许跳过准备阶段、选择有限改变和自行确认目标，减少门槛与自我评价压力。
- 替代方案既可留在当前实验中，也可升级为完整七步习惯项目，兼顾快速试验和长期培养。
- 延续现有视觉骨架和交互规则，使第三类行为看起来属于同一个产品，而不是外挂模块。

## 影响

- 数据库新增旧习惯项目、具体旧行为、对策、观察和替代方案表，schema 版本升级。
- Rust 后端新增第三类工作流的 CRUD、状态转换、删除保护备份和长期习惯关联命令。
- 首页、应用路由、TypeScript 类型和 API 增加第三入口与工作台。
- 全量 JSON 导入导出加入新表并升级格式；旧格式继续按缺失表兼容。
- `DESIGN.md` 和实现记录需要补充第三类工作流的布局、状态和文案规则。

## 与现有决策的关系

- 补充 ADR-0002 和 ADR-0014，形成长期习惯、一次性行为、终止旧习惯三类入口。
- 遵守 ADR-0001、ADR-0005 的本地优先与离线核心路径。
- 遵守 ADR-0017、ADR-0020 的可恢复删除与可选名称确认。
- 沿用 ADR-0019、ADR-0021、ADR-0022、ADR-0023、ADR-0024 的渐进披露、状态栏、理论抽屉和协调视觉系统。

## 未采用方案

### 把终止旧习惯做成一次性任务的一个诊断分支

未采用。旧习惯需要多个具体行为、跨情境观察和替代生命周期，结束条件与单次任务不同。

### 同时平铺全部输入框

未采用。用户应能看见完整的对策地图，但无需同时面对十组待填写内容。

### 自动判断用户已经戒除

未采用。观察证据只能帮助用户判断，不能代表永久状态，也不应制造连续打卡压力。
