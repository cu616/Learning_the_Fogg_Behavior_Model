# ADR-0020：紧凑操作与可选名称确认

- 状态：已接受
- 日期：2026-08-22

## 背景

首页和工作台的高频操作大量使用完整句子，例如“展开管理”“新建长期设计”和“返回首页”，造成视觉噪声。项目永久删除还要求逐字输入可能很长的名称；批量整理时负担较高，而删除前已经有一次明确确认和自动完整保护快照。

## 决定

1. 展开、返回、新建、编辑、复制、归档和删除等含义明确的高频操作优先使用简洁离线符号；图标按钮必须保留 `title`、`aria-label` 和焦点样式。
2. 输入框旁的新建动作使用加号或“添加”两个字，不重复对象全称；流程选择、状态改变和不可从上下文明确判断的动作继续使用文字。
3. 长期项目和一次性行为永久删除始终保留一次明确确认，并继续在后端删除前创建完整保护快照。
4. “删除前输入完整名称”改为数据管理中的本机界面偏好，默认关闭；开启时恢复逐字输入校验。该偏好保存在本机 WebView 存储中，不进入个人行为数据导出。
5. 后端仍要求收到完全匹配的对象名称；关闭输入校验时由前端使用当前对象名称完成调用，因此不会放宽删除目标校验或保护快照约束。

## 理由

- 图标和短标签能让高频界面更紧凑，悬停提示及无障碍名称仍保留可理解性。
- 单次确认加自动备份已经提供可恢复边界，名称逐字输入更适合作为可选的高安全模式。
- 界面偏好不属于行为实验内容，不随 JSON 导出迁移可以保持导出语义清晰。

## 影响

- 首页、长期工作台、一次性工作台和数据管理页采用统一的紧凑图标按钮样式。
- 数据管理增加删除确认偏好；默认删除不再弹出名称输入框。
- ADR-0015 和 ADR-0017 中永久删除、二次确认与保护快照原则继续有效；其中“要求再次输入名称”由本 ADR 调整为可选策略。

## 未采用方案

### 完全取消删除确认

未采用。永久删除仍应清楚告知范围，尤其是长期项目包含配方与实践历史。

### 所有按钮都只显示图标

未采用。流程决策和不常见动作只用符号容易产生歧义，简洁不应牺牲判断准确性。
