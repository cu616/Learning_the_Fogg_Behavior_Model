# ADR-0012：响应式双列排版与信息密度

- 状态：已接受
- 日期：2026-08-22

## 背景

当前 MVP 的多数表单采用“一行一个字段”，项目首页也采用“一行一个项目”。在桌面宽窗口中，这会产生过长的输入框和大量未被利用的横向空间，同时增加页面纵向长度，用户需要频繁滚动，难以同时比较相关信息。

用户希望把功能平行、意义相近、内容通常较短的字段排成一行两个，并让首页一行展示两个习惯项目。与此同时，长文本、核心任务和需要集中注意的区域不适合被机械地压缩成半宽。

## 决定

### 1. 使用语义化双列布局

- 桌面宽度充足时，功能平行、层级相同、内容较短的控件默认采用两列布局。
- 两列必须表达清楚的对应或并列关系，不能只为填满空间而任意拼接字段。
- 每个字段组使用统一的栅格、标签位置、间距和高度，便于左右比较。
- 实现上优先使用响应式 CSS Grid，如 `repeat(2, minmax(0, 1fr))`，避免固定像素宽度。

### 2. 以下内容继续独占整行

- 最终愿望等当前步骤的核心输入；
- 实践感受、原因说明等预期较长的文本；
- 行为集群、焦点地图、能力链等可视化画布；
- 配方预览、诊断结果和重要提示；
- 需要按先后顺序完成、并排后可能造成误解的字段。

### 3. 典型双列组合

- 原行为｜简化后的微行为；
- 基线行为｜可选扩展；
- 锚点最后动作｜地点；
- 频率｜来源或分类；
- 提升的技能｜学习或练习方法；
- 所需工具｜可获得的资源；
- 庆祝方式的自然度｜成功感；
- 数据设置中的相关短配置项。

具体页面可以根据内容长度跨两列，但不应重新退回所有字段默认全宽。

### 4. 首页使用项目卡片网格

- 桌面宽度充足时，习惯项目以两列卡片网格展示，即一行两个项目。
- 每张卡片显示项目名称、状态、当前步骤或当前实践摘要，以及主要操作。
- 卡片高度应尽量一致；操作按钮不应挤占项目名称区域。
- 搜索、筛选和新建区域位于网格上方，不与单张项目卡绑定。

### 5. 响应式回退

- 中等及以上窗口使用双列；窄窗口自动回退为单列。
- 双列布局不能产生过窄的文本框、标签换行堆叠或按钮遮挡。
- 工作台采用 ADR-0010 的三栏结构时，若中间操作区宽度不足，应先折叠右侧帮助或左侧摘要，再决定表单是否回退单列。
- 不以缩小字体作为容纳双列内容的主要办法。

### 6. 控制页面长度与视觉节奏

- 同类短字段放入有标题的紧凑分组，减少重复标签和大块空白。
- 可选内容继续使用条件展开或折叠，不因采用双列而一次显示全部字段。
- 页面纵向间距用于区分阶段和语义组，不在每个输入框之间重复使用过大的间隔。

## 理由

- 更充分利用桌面应用的横向空间。
- 减少滚动距离，让用户更容易同时查看和比较相关字段。
- 首页两列卡片能在一个视野内呈现更多习惯项目。
- 语义化而非强制双列，可以兼顾信息密度、可读性和核心任务的注意力。
- 响应式回退保证小窗口仍然可用。

## 影响

- 当前应用容器最大宽度和工作台宽度需要重新评估；现有 `max-width: 860px` 可能不足以承载新的桌面布局。
- 首页项目列表要从纵向 Flex 列表改为响应式 Grid。
- 各步骤组件需要增加字段组容器以及跨列规则。
- 视觉验收需要覆盖宽屏、中等窗口和窄窗口，检查溢出、换行、空白与滚动长度。
- 本决策只改变排版，不改变字段含义、保存逻辑或步骤顺序。

## 与现有决策的关系

- 补充 ADR-0010 的三栏工作台与条件展开设计。
- 不改变 ADR-0002 的七步主工作流。
- 窄窗口适配继续遵守可访问性和离线核心路径要求。

## 未采用方案

### 所有字段强制两列

未采用。长文本、可视化和核心输入被压缩后会降低可读性，并可能让用户误解字段之间的关系。

### 保持所有项目一行一个

未采用，因为桌面宽度被大量浪费，管理多个习惯时需要不必要的纵向滚动。

### 通过缩小字体提高信息密度

未采用。信息密度应主要通过合理分组、双列和折叠实现，而不是牺牲可读性。
