# ADR-0005：首版 AI 能力策略

- 状态：已接受
- 日期：2026-08-21

## 背景

蓝图第 10 节把 AI 定义为可选助手，并指出"首个版本可以用规则和书中固定方法完成全部关键判断，AI 后续作为增强层加入"。docs/README 将"AI 能力采用本地模型、可选外部 API，还是两者兼有"列为待决策事项。

## 决定

- 首版（MVP）完全采用规则与书中固定方法实现，不接入任何 AI 或在线模型。
- 核心七步工作流在无网络、无 AI 的情况下完整可用。
- 行为集群启发、锚点建议、庆祝建议、障碍解释等，首版使用内置模板 / 规则库完成。
- 数据层与辅助栏的内容来源设计为可替换，为未来接入 AI 预留接口，但首版不实现该接口。

## 理由

- 与本地优先（ADR-0001）和"核心流程离线可用"约束一致。
- 降低首版复杂度与隐私风险，避免任何个人数据外发。
- 书中已提供足够明确的方法和判断标准，规则实现即可覆盖全部关键判断。

## 影响

- 首版无任何网络调用。
- 辅助栏内容来自本地知识库与内置规则，而非模型生成。
- 不引入 API 密钥管理、模型调用、请求失败与成本控制等实现面。
- 未来若增加 AI，需单独 ADR 决定采用本地模型、可选外部 API 或双模式，并明确"发送数据前取得用户同意"。

## 未采用方案

### 首版即接入可选在线大模型

未采用。会增加隐私风险、网络依赖与实现复杂度，与本地优先定位冲突。

### 首版使用本地小模型

未采用。首版阶段引入本地推理的工程与体积成本过高，收益有限。
