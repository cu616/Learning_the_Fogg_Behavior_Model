# ADR-0038：界面不展示原书页码与情境化说明重构

- 状态：已接受
- 日期：2026-08-23
- 调整：[ADR-0037](./ADR-0037-跟做式说明与行为设计排练册.md)
- 延续：[ADR-0034](./ADR-0034-离线用户说明与方法学习路径.md)

## 背景

行为设计排练册在每条方法卡底部显示“原书定位：PDF 物理页……”后，虽然提高了回查性，却把工作界面变成了带出处脚注的资料卡。对没有读过原书的用户，这类信息既不能帮助当前判断，也强化了模板化、AI 摘要式的视觉感。说明书中的三条同规格工作流卡和泛化“常见问题”同样没有提供足够的情境与决策依据。

浏览器演示模式还缺少终止旧习惯工作台的读取链路；数据与隐私页误用了首页大型头图骨架，导致空白区域过大、主体操作不在首屏。这些问题会妨碍本地预览对真实导航的验收。

## 决定

1. 软件界面不再展示 PDF 物理页码、章节定位或书目式来源尾注。原书回查证据继续保留在 `knowledge/`、研究资料和决策文档中，不丢失知识可追溯性。
2. 行为设计排练册只保留与当前操作直接相关的结论、自问问题、判断要点和一个立即动作。
3. 使用说明的工作流选择改为一个决策问题和三条去向，不再使用三张同规格功能卡。
4. 长期习惯案例改用有生活约束的办公室久坐情境；一次性行为改用预约年度体检；“常见问题”改为从真实现场出发的卡点处理建议，避免“本轮只改”等固定教程句型。
5. 数据与隐私页使用独立的紧凑页头和任务面板，不复用首页角色头图。动漫人物只占用可控的局部版面，不遮挡数据操作。
6. 浏览器演示数据覆盖终止旧习惯的项目、具体行为、对策、观察和替代读取/保存链路，以及数据页的备份与个人参考库链路，用于本地导航回归。
7. 这些变更不修改 SQLite 结构，不改变离线与隐私边界，也不生成 EXE 或安装包。
8. 面向普通用户的界面不以 `B = MAP`、`P / A / M` 单字母作为视觉标题。首次解释使用 `Motivation · Ability · Prompt` 全称，后续操作统一使用“动机、能力、提示”中文名称；模型内部字段仍可保留字母枚举。
9. 浏览器演示模式覆盖微习惯方案的新建、重命名、状态更新与删除命令，使设计状态票据中的按钮可以按真实流程回归。

## 理由

- 工作时最重要的是完成当前判断；页码适合知识库维护，不适合占据交互卡片的结尾。
- 有人物、有约束、有具体下一动作的案例，比抽象愿望更容易迁移到自己的生活。
- 真实卡点处理表能直接支持下一轮设计，价值高于泛化问答。
- 独立页面骨架能避免全局主题规则把数据工具页变成空白海报。
- 完整浏览器演示链路才能可靠检查入口和阶段跳转，而不把 mock 缺失误判为产品功能故障。

## 影响

- ADR-0037 中关于界面展示 PDF 物理页码的第 2、3 条由本决定调整，其余排练册结构继续有效。
- `foggNotes.ts` 不再保存界面展示用的 `source` 字段，`FoggNotePanel.tsx` 不再渲染来源尾注。
- `UserGuide.tsx`、`DataSettings.tsx` 与漫画主题样式发生较大排版调整。
- `devMock.ts` 可以在 `?mock=1` 下打开并切换终止旧习惯五阶段，也可正常载入数据页。
- 使用说明不再采用口号式“对自己更狠”开场，也不使用巨型 `M / A / P` 字母卡；诊断表直接显示中文因素名称。
- `?mock=1` 下可以验证微习惯方案的编辑、稳定、暂停、恢复与删除交互。

## 备选方案

### 把页码缩小或藏进提示气泡

仍会让用户把注意力从当前动作移向资料出处，也继续维护一套无操作价值的界面元数据，拒绝。

### 保留常见问题并微调文案

问答列表仍然缺少诊断路径，不能解决“下一轮改什么”，拒绝。

### 只修复数据页 CSS，不拆分页面骨架

以后首页样式变化仍可能再次污染工具页，拒绝。
