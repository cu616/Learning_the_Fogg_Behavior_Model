# ADR-0040：私人测试包与可分发版本分离

- 状态：已接受
- 日期：2026-08-24
- 关联：[ADR-0035](./ADR-0035-私用动漫IP视觉主题与可替换资产层.md)、[ADR-0039](./ADR-0039-Android个人测试包与移动端边界.md)

## 背景

用户希望把 Windows 版本和 Android 版本交给其他人使用。当前分支仍包含仅按个人使用场景引入的《孤独摇滚！》原版人物素材，并且 Windows 可执行文件没有商业代码签名证书，Android 第一阶段也只约定调试签名。直接把这些产物称为“公开发布版”会同时掩盖素材授权、安装信任提示和更新签名三个问题。

## 决定

1. 构建工作在项目内部区分两条线：当前素材下只作为私人测试构建；可分发版本必须先替换为自有、开源许可或已获明确授权的视觉素材。该内部分类不写入应用名称、安装程序标题或产品界面。
2. Windows 同时提供便携 `app.exe` 与 NSIS `Setup.exe`。便携版可直接运行；安装版负责快捷方式、卸载入口与运行时安装检查，更适合普通测试用户。
3. 没有可信代码签名证书时，Windows 安装程序必须说明可能出现“未知发布者”或 SmartScreen 提示，不把未签名包描述为正式可信发布版。
4. Android 第一阶段继续生成 ARM64 调试签名 APK，只供设备兼容性和交互测试。面向长期分发前，另行建立由用户自己保管的发布密钥，并记录包名、密钥备份和升级策略。
5. Windows 与 Android 数据各自保存在设备本地，不自动同步。第三方测试者的数据不得通过开发者服务收集。

## 理由

- Setup 改善的是安装和卸载体验，并不自动解决软件签名或素材授权。
- Android 调试签名可以尽快验证真机，但调试密钥不应成为长期分发身份。
- 把测试包与可分发版本明确分开，可以继续验证产品，又不会让临时素材和临时签名意外进入公开发布链路。

## 影响

- 当前生成的 Setup 和 APK 在项目记录中归为私人测试构建，但产品界面和文件名不增加测试标签。
- 对外分享前需要完成素材替换；若希望减少系统安全警告，还需要准备 Windows 代码签名证书和 Android 发布密钥。
- Android 发布密钥一旦用于对外版本，后续更新必须持续使用同一密钥；密钥和密码不得提交到仓库。

## 备选方案

### 直接把当前包公开发送

无法解决原版动漫素材授权、Windows 未签名提示和 Android 调试签名的升级问题，不采用。

### 只发送便携 EXE

技术上可行，但普通用户缺少快捷方式、卸载入口和运行时提示。保留便携版作为高级用户选项，同时提供 Setup。

### 立即创建正式签名密钥

Windows 证书需要用户选择可信证书来源，Android 密钥需要由用户长期保管密码和备份。当前没有足够的密钥管理信息，暂不擅自创建。
