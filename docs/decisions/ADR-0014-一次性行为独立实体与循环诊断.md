# ADR-0014：一次性行为独立实体与循环诊断

- 状态：已接受
- 日期：2026-08-22

## 背景

ADR-0009 已接受一次性任务作为七步习惯设计的补充工作流，但当时明确不确定数据结构，也不把功能纳入 MVP。用户现要求在当前本地软件中实现该流程。一次性行为只需越过这一次行动线；如果复用长期习惯项目和七个步骤，会制造行为集群、焦点地图、长期锚点与重复练习等无关填写负担。

## 决定

1. 本版本正式把一次性行为纳入软件，与长期习惯设计并列为第二类入口；七步习惯设计仍是长期重复行为的主流程。
2. 一次性行为采用独立的 `one_time_task`、`one_time_diagnosis_round` 和 `one_time_task_event` 实体，不给 `habit_project` 增加大量只适用于单次任务的可空字段。
3. 默认界面只显示任务、完成标准和当前下一动作；截止时间、完成证据、价值判断、能力链和提示细节按需展开。
4. 诊断是循环路由，不是 P、A、M 三页问卷。引导入口严格按提示→能力→动机检查，也允许用户直接选择已经确认的障碍。每轮只保存一个主要障碍和一个主要调整，随后返回行动页。
5. 状态为草稿、已准备、进行中、已完成、已取消、已委托、已延期和已归档，不设置“失败”。诊断轮次和行动事件保留历史，但默认折叠。
6. 首版只保存逻辑提示、时间和地点，不创建操作系统通知；核心流程完全离线。
7. 当用户确认行为需要长期重复时，可将任务转换为七步习惯项目；新项目的初始愿望保留原任务、完成标准和下一动作，原一次性任务保留并记录转换目标。
8. 三张新表纳入完整备份、全量导入导出；单项目导出仍只用于长期习惯项目。导出格式升级见 ADR-0013。

## 理由

- 独立实体能清楚表达单次任务的关闭状态、诊断轮次和转换关系，同时保护已经稳定的长期习惯模型。
- 渐进披露和每轮只调整一个因素，符合一次性任务蓝图的低输入负担原则。
- 显式保存逻辑提示避免引入系统权限、平台差异和后台调度风险。
- 事件历史让取消、委托、延期和重新诊断都成为可回溯的设计决定，而非失败标签。

## 影响

- 数据库版本升级到 4，业务表增加到 28 张。
- 首页同时管理长期习惯设计和一次性行为；两类卡片共享响应式双列排版，但筛选和状态文案保持独立。
- 需要新增 Rust 命令、TypeScript API、一次性行为工作台、迁移测试和导入导出映射。
- 操作系统通知若以后实现，必须另建 ADR；本决定不授权通知权限或后台服务。

## 与现有决策的关系

- 将 ADR-0009 中的“未来补充工作流”推进为当前已实现范围，其余原则继续有效。
- 补充而不替代 ADR-0002 的七步习惯设计。
- 遵守 ADR-0001 和 ADR-0005 的本地优先、离线可用要求。
- 界面继续遵守 ADR-0012 的语义化双列与窄屏回退。

## 备选方案

### 泛化 `habit_project`

未采用。两类流程的状态、历史和字段生命周期差异很大，泛化会产生大量可空字段并提高旧数据迁移风险。

### 把诊断保存为一段 JSON

未采用。首版字段已经明确，结构化列更利于历史展示、导出验证和后续规则分析。

### 首版直接创建系统提醒

未采用。提醒涉及权限、后台运行和跨平台行为；保存逻辑提示已经能完成本轮行为设计。
