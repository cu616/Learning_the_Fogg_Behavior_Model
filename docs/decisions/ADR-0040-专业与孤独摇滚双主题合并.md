# ADR-0040：专业与孤独摇滚双主题合并

- 状态：已接受
- 日期：2026-08-25
- 补充：ADR-0032、ADR-0033、ADR-0036、ADR-0037、ADR-0038
- 替代范围：协作者分支 ADR-0041 中“孤独摇滚版本长期独立、不得合并回主版本”的决定

## 背景

`main` 已发展为 V0.2：包含长期习惯、一次性行为、终止旧习惯三类工作流，支持 Windows 与 Android，共享本地 SQLite 数据和离线资源。协作者从较早版本创建了 `fogg_Bocchi-the-Rock` 分支，形成粉、黄、浅蓝、黑四色漫画界面，并加入《孤独摇滚！》角色素材和主题化组件。

直接用该分支覆盖主版本会丢失移动入口、自定义背景、视口级错误反馈和 V0.2 后续文档；继续维护两个独立应用则会让行为工作流、数据库与修复逐渐分叉。用户希望在一个软件内保留专业模式和动漫模式。

## 决定

1. `main` 的 V0.2 业务代码、三类工作流、数据库、移动入口和离线能力继续作为唯一产品内核。
2. 应用提供两套可切换的视觉主题：
   - “专业模式”为默认主题，沿用森林背景、深色半透明工作面和七步语义色；
   - “孤独摇滚模式”为可选主题，复用协作者分支的漫画色谱、纸张表面、角色素材和主题化装饰。
3. 主题切换放在“数据与外观”页面，桌面端与 Android 使用同一偏好。切换即时生效，不要求重启应用。
4. 主题偏好只保存在本机 `localStorage`，不写入行为数据库，不随习惯 JSON 备份导出，也不发送网络请求。
5. 专业主题继续使用用户选择的本地自定义背景。孤独摇滚主题使用自己的离线漫画背景；切回专业主题时恢复原有自定义背景偏好，不删除图片。
6. 主题实现以语义角色和根节点主题标记隔离。动漫主题样式作为独立本地样式层加载，不能覆盖或复制业务状态；主题专属人物和装饰在专业模式下不占据布局。
7. 两套主题共享相同的表单、导航、自动保存、错误反馈、拖拽替代操作和无障碍语义。主题不得改变步骤顺序、字段含义、数据结构或行为状态。
8. Android 继续遵守现有触控目标、安全区和高密度排版规则。动漫装饰在窄屏只作为次级视觉线索，不能挤占主要输入和行动空间。
9. 协作者分支提交历史通过 Git 合并保留；发生冲突时以当前 `main` 的产品逻辑为准，选择性接入分支的视觉资产和主题组件。
10. 《孤独摇滚！》素材继续随来源说明和校验信息保存并完全离线使用。仓库保持私有；若未来公开发布或商业分发，仓库所有者需另行确认第三方素材授权，不能把本 ADR 视为授权证明。

## 理由

- 单一产品内核避免桌面与移动、专业与动漫版本产生不同的数据语义和修复进度。
- 独立主题层比把两套颜色混进同一组选择器更容易回退、测试和维护。
- 默认专业模式保留现有用户预期；动漫模式由用户主动选择，不影响严肃或低干扰的使用场景。
- 本机偏好与个人行为数据分离，符合本地优先和可恢复原则。
- 保留分支父提交能够明确协作者贡献来源，而不是把成果复制成无历史的新文件。

## 影响

- 前端新增主题偏好、主题切换控件、动漫主题样式层和少量主题专属装饰组件。
- `app/public/themes/kessoku/` 中的本地素材与来源说明进入合并后的仓库。
- `DESIGN.md` 和使用说明增加双主题边界与测试要求。
- 不新增数据库迁移，不改变已有项目、日志、诊断、备份或导入导出格式。

## 备选方案

### 用协作者分支直接覆盖主版本

会回退 V0.2 的移动端、自定义背景和错误反馈，并让已有数据能力面临不必要风险，不采用。

### 继续发布两个完全独立的软件

短期冲突少，但每次工作流修复都需要双份移植，最终会产生两套不兼容产品，不采用。

### 把动漫色值直接混入现有 `App.css`

选择器与令牌难以隔离，主题切换和回归测试成本高，也容易让专业主题被动漫规则污染，不采用。
