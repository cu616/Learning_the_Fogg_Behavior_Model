# ADR-0035：Android 一次性行为 Demo 与移动入口

- 状态：已接受
- 日期：2026-08-23
- 补充：ADR-0001、ADR-0004、ADR-0014、ADR-0024、ADR-0034

## 背景

当前应用以 Windows 桌面端为首发平台，已经包含长期习惯设计、一次性行为和终止旧习惯三类工作流。用户希望先制作一个 Android 竖屏 Demo，只移植一次性行为，并继续沿用现有森林背景、深色半透明材质和 WeTab 启发的视觉语言。

桌面工作台依赖宽屏状态栏、中央画布和按需理论抽屉。直接把桌面三栏页面缩窄会造成触控目标过小、支持信息争夺首屏、输入框堆叠和系统返回行为不明确。另一方面，一次性行为的 Rust 命令、SQLite 实体、诊断轮次和事件历史已经稳定，不应在移动端另建一套不兼容的数据模型。

## 决定

1. Android Demo 继续使用 Tauri 2、React、Rust 和 SQLite，与桌面端共享一次性行为领域模型、数据库迁移和命令；不建立第二套移动数据库协议。
2. 前端增加独立的 Android 移动入口。Android 包只呈现一次性行为的创建、列表、明确动作、P→A→M 按需诊断、采取行动、诊断历史和本地自动保存；桌面入口仍显示原有三类工作流。
3. Android Demo 暂不呈现“转为长期习惯”入口。底层转换命令保持不变，待长期习惯移动工作流完成后再开放，避免把用户送入未适配的桌面页面。
4. 移动端不压缩桌面三栏，而采用单列主内容：
   - 顶部应用栏承载返回、任务名称、流程返回、状态和笔记入口；
   - 三段流程导航位于主内容顶部；
   - 行为状态默认不常驻，按需以覆盖面板出现；
   - 福格模型笔记继续使用覆盖抽屉；
   - 表单、诊断和行动页一次只突出一个主要决定。
5. 触控目标不小于 48dp，相邻目标至少保留 8dp 间距；输入正文不小于 16px；固定区域使用安全区内边距，不遮挡状态栏、导航栏和手势区。
6. 布局按可用窗口宽度响应，而不是锁定手机方向。紧凑宽度使用单列；较宽手机横屏和平板可增加内容宽度或卡片列数，但不把控件无节制拉伸。
7. 继续使用离线内置森林背景、系统字体、本地 SVG/内联图标和现有深色透明令牌。移动端用较少的模糊层和稳定的深灰叠层保证 WebView 性能；系统请求减少透明度或减少动态效果时提供不透明、低动效回退。
8. Demo 不加入账号、联网同步、在线字体、在线图片、AI、系统通知或后台提醒。逻辑提示仍只保存在本地，不暗示系统会自动弹出通知。
9. Android 生成项目、SDK/NDK 路径和构建说明进入版本库或本地文档；大型 SDK、模拟器磁盘、Gradle 缓存和编译产物不进入 Git。

## 理由

- 共享领域模型可以保留桌面端已经验证的诊断历史、本地保存与无评判状态语义。
- 独立移动入口能真正按触控和竖屏重排，而不会破坏桌面端已经稳定的三类首页。
- 先移植一次性行为形成规模可控的端到端闭环，可验证 Tauri Android、SQLite、WebView 和安装包，再决定其他两类工作流的移动形态。
- 状态和理论信息按需覆盖，符合中央当前任务优先与渐进披露原则。
- 不开放尚未移植的长期习惯入口，避免移动 Demo 出现断裂路径。

## 影响

- `app/src` 增加移动首页和平台入口判断；一次性工作台增加移动显示模式，但桌面默认行为不变。
- `app/src-tauri/gen/android` 由 Tauri 初始化并用于 APK/AAB 构建。
- Android 设备上的 SQLite 数据独立存于该应用的私有数据目录，不会自动与 Windows 数据库同步。
- 首个 Demo 以本地调试 APK 为验收物；发布到应用商店、正式签名、系统通知和跨设备数据迁移分别需要后续决策与测试。

## 备选方案

### 新建独立 Flutter 或原生 Compose 应用

原生体验上限更高，但会立即复制领域逻辑、数据库迁移和测试，首个 Demo 成本过高，暂不采用。

### 直接让完整桌面首页在窄屏响应

会把未移植的长期习惯和终止旧习惯暴露给用户，也容易保留桌面信息密度，拒绝。

### 只制作浏览器 PWA

无法验证真实 Android 安装、Tauri SQLite 命令和应用私有存储，不满足本次 APK Demo 目标。
