# ADR-0004：桌面技术栈与首发平台

- 状态：已接受
- 日期：2026-08-21

## 背景

蓝图第 12 节将 Tauri + React + SQLite 列为"建议但尚未确认"的技术方向，docs/README 也将"桌面技术栈与首发操作系统"和"本地数据库、迁移与备份格式"列为待决策事项。进入实现前需要确定技术栈与首发平台，以降低后续返工。

## 决定

- 首发平台仅支持 Windows（用户当前环境为 Windows 11）。
- 桌面容器采用 Tauri 2.x。
- 界面采用 TypeScript + React。
- 本地数据库采用 SQLite（由 Tauri 的 Rust 后端访问）。
- 本地知识内容沿用现有 `knowledge/` 的 Markdown / JSONL 文件，作为辅助栏的只读知识源。
- 备份以 SQLite 快照为主，配合可读的 JSON / Markdown 导出。

## 理由

- Tauri 安装体积小、内存占用低，契合"本地优先、个人长期使用"的产品定位。
- 现有 `knowledge/` 已经是 Markdown / JSONL，直接复用可省去知识内容的二次格式转换。
- SQLite 是单文件数据库，事务可靠，易于备份、导出与迁移。
- 仅 Windows 首发可显著降低打包、签名与测试成本，符合"先自用后分发"的定位；Tauri 本身支持跨平台，未来扩展成本可控。

## 影响

- 需要同时具备 Rust 与 Node.js 工具链。
- 数据访问集中在 Rust 侧，需单独设计数据层、迁移机制与错误处理（见后续 ADR）。
- 首版不需要处理 macOS / Linux 打包签名。
- 本地知识库以只读方式随应用打包，用户不可直接改坏内置内容。

## 未在本决策中确定

- 数据库迁移与 schema 版本管理方案；
- 自动备份保留策略；
- 是否启用本地数据加密和应用锁；
- 单个习惯与完整数据的导出/导入格式；
- 是否需要系统通知以及提醒策略。

这些事项仍需单独 ADR。

## 未采用方案

### Electron + React + SQLite

未采用。生态成熟但安装体积大、内存占用高，对本地个人工具不划算。

### 纯 Web（PWA + localStorage）

未采用作为主方案。浏览器本地存储可能被清理，备份、迁移与大量结构化记录的可靠性不足（见 ADR-0001）。
