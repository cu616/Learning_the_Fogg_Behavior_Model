## M0：工具链与脚手架

- 安装 Node.js、Rust 工具链、Tauri CLI；
- 初始化 Tauri + React + TypeScript 项目，确认 Windows 下可编译、可启动空窗口；
- 接入 SQLite（rusqlite 或 sqlx），执行 `concept` 草案的 v1 迁移，建 14 张表；
- 把 `knowledge/references/*.json` 复制进应用资源目录，验证可只读加载。

**验收**：`cargo tauri dev` 能在 Windows 启动窗口；本地 SQLite 文件按 schema 建表；参考库 JSON 可被前端读取。

## M1：项目 CRUD + 首页 + 自动保存

- `habit_project` 的新建、命名、复制、归档；
- 首页：项目列表 + 筛选（设计中/实践中/稳定/暂停/归档）+ 搜索 + 愿望领域分组；
- 字段级自动保存，异常退出后重启恢复最近状态。

**验收**：可创建/复制/归档多个项目；筛选与搜索正确；输入后直接关闭应用重启不丢数据（MVP 第 2、12 项）。

## M2：七步工作台（1–6 步）

- 统一框架：顶部进度 + 中央工作区 + 右侧辅助栏 + 底部导航；
- 第 1 步：愿望输入 + 类型初判 + 最终愿望确认（`aspiration`）；
- 第 2 步：行为集群增删改 + 启发问题（`behavior_option`）；
- 第 3 步：焦点地图拖拽 + 黄金行为选择（`focus_placement` + `golden_behavior`）；
- 第 4 步：能力链五因素 + 缩小规模/入门步骤 + 最低动机测试（`ability_assessment` + `tiny_behavior`）；
- 第 5 步：候选锚点 + 最后动作 + 配方前两部分（`anchor`）；
- 第 6 步：庆祝实验 + 配方卡 + ABC 演练 + 生成配方 v1（`celebration` + `recipe_version`）；
- 可返回上一步修改。

**验收**：第 1–6 步按序可用、可回退、自动保存；第 6 步完成后生成 `recipe_version` v1、项目 `phase` 转 `ready`（MVP 第 3、4、5、6、7、8 项）。

## M3：第七步（实践 + 诊断 + 扩展）

- 今日快速记录（六种结果），成功时先感受成功；
- 诊断：提示→能力→动机 顺序，按反馈表建议返回步骤，每次只改一个因素（`obstacle_diagnosis`）；
- 配方版本：锚点/微行为/庆祝/扩展变更生成新版本，历史可回查（`recipe_version`）；
- 重复（不清零、可暂停/恢复）与扩展（仅可选，保留原基线）。

**验收**：六种结果可快速记录；`practice_event` 正确绑定当时 `recipe_version`；诊断给出正确返回步骤；修改生成新版本（MVP 第 9、10、11 项）。

## M4：参考库接入 + 辅助栏

- 每步右侧辅助栏随问题变化，含书中要点、误区、正反例、PDF 页码，可展开知识库原文；
- 第 2 步可浏览「微习惯配方库」启发；第 5 步可选用「锚点模板」；第 6 步可浏览「庆祝方式库」与「肯定成功方式」；
- 选用时文本复制进用户实体并标注来源，不修改内置内容。

**验收**：辅助栏随步骤正确显示并标注页码；三个参考库可浏览、选用并正确落库（MVP 第 14、16 项）。

## M5：备份/导出/恢复 + 收尾

- 手动备份 + 自动滚动备份；恢复前显示备份摘要；
- 导出单个习惯与全部项目（JSON/Markdown，用 `uuid` 做身份），导入恢复；
- 全界面无评判用语文案审查，无连续打卡清零/惩罚机制；
- 离线可用确认（无网络请求）。

**验收**：备份/导出/恢复全链路可用；全界面无禁用词；断网下核心流程完整可用（MVP 第 13、15、1 项）。

## 非目标（首版不做）

- 云账户、社交/排行榜、跨设备实时同步、复杂游戏化、依赖在线大模型的功能、群体协作系统、医疗建议（见蓝图第 11 节）。

## 风险与依赖

- **工具链**：Tauri 在 Windows 需要 Rust（MSVC 或 GNU 工具链）+ Node.js，首次编译耗时较长。
- **迁移可靠性**：SQLite 迁移与备份恢复需单独 ADR，实现前需先定方案。
- **视觉风格**：首版采用简洁、浅色、无评判的中性视觉，正式视觉规范待定。
