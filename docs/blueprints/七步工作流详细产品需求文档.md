# 七步工作流详细产品需求文档（PRD）

- 文档版本：0.1（长期习惯七步的原始需求基线）
- 日期：2026-08-21
- 状态：草案（待评审）
- 上游依赖：`软件大纲蓝图.md` v0.1、ADR-0001 / 0002 / 0003 / 0004 / 0005
- 原始适用范围：首版 Windows MVP；V0.2 已共享至 Android，现行响应式与平台规则以 ADR-0035～0038 和 `DESIGN.md` 为准

> 本 PRD 把蓝图转成可实现、可测试的需求。每条核心需求尽量附带验收标准（AC），用于后续验收与端到端测试。

---

## 1. 文档目标

1. 为七步工作台、今日实践、多习惯管理和本地数据管理提供逐字段、逐交互的明确说明。
2. 为开发提供可直接实现的规则与校验标准。
3. 为后续"概念数据模型与数据库草案""页面地图与线框图""MVP 迭代计划"提供输入。

## 2. 术语与缩写

| 术语 | 含义 |
|---|---|
| B=MAP | 动机 × 能力 × 提示，三要素同时具备行为才发生 |
| 愿望 / 成果 / 行为 | 方向 / 可衡量结果 / 可执行动作，三者的区分见术语速查 |
| 行为集群 | 围绕愿望发散出的候选具体行为集合 |
| 焦点地图 | 影响（纵轴）× 可行性（横轴）的二维筛选 |
| 黄金行为 | 有效、想做、能做三者同时满足的行为 |
| 能力链 | 时间 → 资金 → 体力 → 脑力 → 日程 |
| 微行为 / 入门步骤 / 基线 / 扩展 | 最小行为 / 只做开端 / 状态差时也保证完成的最低量 / 自愿多做 |
| 锚点 / 最后动作 | 既有可靠事件 / 锚点结束、新行为开始的精确时点 |
| 庆祝 / 发光 | 行为后立即制造真实积极情绪 / 庆祝时的成功感 |
| 微习惯配方（ABC） | 锚点 → 微行为 → 庆祝 |
| 配方版本 | 某一时刻完整可执行的配方快照 |
| 实践事件 | 一次现实实践的结果记录 |

## 3. 全局需求（跨所有步骤）

### 3.1 自动保存

- 所有文本、选择、评分、拖拽位置在**失焦或变更后即时保存**，用户无需手动点"保存"即可退出后继续。
- 顶部保留"自动保存状态"指示（已保存 / 保存中 / 保存失败）。
- 应用异常退出后，重启回到最后编辑的项目与步骤，已输入内容不丢失。

**AC**：在任意步骤输入后直接关闭应用，重启后输入内容完整恢复。

### 3.2 配方版本与可回溯

- 第 6 步完成并确认"放入现实试验"时生成第一个配方版本（v1）。
- 下列要素之一发生变更，且用户确认后，生成新配方版本：锚点最后动作、微行为/基线、庆祝方式、扩展后的行为。
- 每个配方版本保存：版本号、创建时间、完整配方快照、变更要素、变更原因（引用 `ProjectChange`）。
- 每个实践事件必须记录 `recipe_version_id`，指向记录当时生效的版本。

**AC**：修改锚点后，历史实践记录仍能显示当时使用的旧配方；新记录指向新版本。

### 3.3 语气与无评判

- 界面与诊断文案不出现"失败""意志力差""不够自律""中断=失败"等表述。
- 未执行时进入诊断流程，把问题指向"配方/设计"，而非用户人格。
- 不提供连续打卡清零、惩罚、羞耻类机制；中断后可直接从原基线继续。

**AC**：全界面检索不到禁用词；"想起来但没做"被引导到第 4 步而非警告。

### 3.4 辅助栏

- 每步右侧辅助栏随当前问题/字段变化，默认折叠。
- 内容项：这一步为什么重要、核心概念、书中判断标准、正反例、常见误区、"我不确定怎么回答"提示、对应 PDF 页码、可展开的知识库原文。
- 辅助栏只读，不改变用户输入。

### 3.5 导航与"稍后决定"

- 顶部显示当前习惯名、七步进度、自动保存状态、返回首页、查看配方草稿。
- 底部提供：返回上一步、保存草稿、标记"稍后决定"、继续下一小步、查看本次修改会影响哪些后续内容。
- 标记"稍后决定"的字段不阻塞流程推进，但会在完成条件里作为未决项提示。

### 3.6 离线可用

- 首版无任何网络调用；全部核心流程离线完成（ADR-0005）。

## 4. 七步详细需求

> 每步结构：前置 → 目标 → 输入与字段 → 交互/工具 → 校验规则 → 完成条件（AC）→ 保存数据 → 边界与错误。

### 4.1 第一步：明确愿望

**前置**：从"新建设计"进入。

**目标**：找到真正想改变的方向，区分愿望、成果、行为。

**输入与字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 原始输入 | 文本 | 是 | 初始"我想……" |
| 输入类型判断 | 枚举：愿望/成果/行为/不确定 | 是 | 软件初判，用户可改 |
| 为什么重要 | 文本 | 否 | 触发第 3 小步 |
| 生活有何不同 | 文本 | 否 | 触发第 4 小步 |
| 最终愿望/成果 | 文本 | 是 | 修正后的表述 |
| 补充说明 | 文本 | 否 | 自由备注 |

**交互与工具**

1. 输入"我想……"。
2. 规则初判输入类型：
   - 含可量化结果（如"减重 5 公斤""读完 10 本书"）→ 成果；
   - 含可观察动作（如"每天跑步""写日记"）→ 行为；
   - 抽象方向（如"更健康""更专注"）→ 愿望。
3. 若判为"成果"或"行为"，提示用户："这更像成果/行为，是否希望把它背后的方向表达为愿望？"，允许坚持原输入。
4. 依次询问"这对你为什么重要""如果改变，生活会有什么不同"。
5. 基于回答生成"最终愿望"草稿，用户可编辑确认。

**校验规则**

- 最终愿望非空即可通过；不强制必须判断为"愿望"。

**完成条件（AC）**

- 用户能用一句话说明真正想改变的方向，并点击"确认，值得继续探索"。

**保存数据**：原始输入、类型判断、最终愿望、重要原因、生活差异、补充说明、修改历史。

### 4.2 第二步：探索行为选项（行为集群）

**前置**：已确认愿望。

**目标**：发散出尽可能多的具体行为，不评价、不承诺。

**输入与字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 行为卡片文本 | 文本 | 是 | 可观察动作 |
| 来源 | 枚举：用户/模板/启发问题 | 是 | 首版无 AI，来源仅这三类 |
| 状态 | 枚举：活跃/暂存/已删除 | 是 | 软删除 |
| 备注 | 文本 | 否 | |
| 生成批次 | 时间 | 是 | 同批启发记录 |

**交互与工具**

1. 回顾已确认愿望（云朵中央显示）。
2. "挥舞魔法棒"发散提示：如果任何事都能做到，可以做什么。
3. 软件按生活场景提供启发问题（早晨/通勤/工作/晚间/压力大时等），并可浏览内置「微习惯配方库」中的场景示例作为启发（标注为书中示例）。
4. 对模糊表达（"多运动""更健康"）给出改写为可观察动作的建议。
5. 从时间、地点、情境继续补充。
6. 检查是否把愿望/成果误写成行为，给出提示。

**校验规则**

- 完成前提示：行为应是"某人能实际做出的动作"；纯抽象词（"更健康"）不被计为行为卡片。

**完成条件（AC）**

- 活跃行为卡片 ≥ 5（软建议 10，无硬门槛），用户点击"进入筛选"。

**保存数据**：行为卡片列表（含来源/状态/备注）、删除与暂存状态、生成批次。

### 4.3 第三步：为自己匹配具体行为（焦点地图 + 黄金行为）

**前置**：存在 ≥1 张活跃行为卡片。

**目标**：找出有效、想做、能做三者同时满足的黄金行为。

**输入与字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 影响评分 | 1–5 整数 | 是 | 对愿望的推动力 |
| 可行性评分 | 1–5 整数 | 是 | 现在能否做到 |
| 是否愿意做 | 布尔 | 是 | 想不想 |
| 黄金行为选择 | 引用行为卡片 | 是 | 选定一个 |
| 选择理由 | 文本 | 否 | 记录为什么 |

**交互与工具**

1. 每张卡片拖入焦点地图（纵轴影响、横轴可行性）。
2. 右上区域（影响高 + 可行性高）自动标为黄金行为候选。
3. 逐项记录愿意度。
4. 对候选检查三标准：有效（影响 ≥ 4）、想做（愿意 = 是）、能做（可行性 ≥ 4）。
5. 选定当前推进的一个黄金行为；其余候选保留在候选库。

**校验规则**

- 三标准作为建议而非硬阻断；用户可坚持选择不满足某项的行为，但需记录理由。

**完成条件（AC）**

- 至少选定 1 个黄金行为；首版一次只推进 1 个，其余进入候选库。

**保存数据**：每张卡片位置、影响/可行性/愿意度、黄金行为选择、选择理由。

### 4.4 第四步：从微习惯开始（能力链 + 容易做分析）

**前置**：已选定黄金行为。

**目标**：让行为简单到低动机、匆忙、疲惫时仍能完成。

**输入与字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 原行为描述 | 文本 | 是 | 黄金行为当前版本 |
| 能力五评估 | 每项枚举：充裕/一般/紧张 | 是 | 时间/资金/体力/脑力/日程 |
| 最弱环节 | 枚举五项之一 | 是 | 规则或用户确认 |
| 简化方式 | 枚举：提升技能/工具资源/缩小规模/入门步骤 | 是 | 可多选 |
| 微行为 | 文本 | 否 | 缩小规模的结果 |
| 入门步骤 | 文本 | 否 | 只做开端 |
| 基线行为 | 文本 | 是 | 状态差也保证完成 |
| 可选扩展 | 文本 | 否 | 自愿多做 |

**交互与工具**

1. 描述黄金行为当前版本。
2. 依次检查五个能力因素并打分。
3. 高亮最薄弱环节（可自动建议，用户确认）。
4. 选择简化方式；在"缩小规模"与"入门步骤"之间可二选一或同时保留。
5. 最低动机测试："当你很累、没时间、心情差时，还能做到吗？"
6. 确认基线与可选扩展。

**示例**（沿用蓝图）

```
原行为：每天跑步 30 分钟
缩小规模：步行 2 分钟
入门步骤：穿上跑鞋
基线行为：穿上跑鞋并走到门外
可选扩展：如果愿意，可以继续步行
```

**校验规则**

- 基线必须通过最低动机测试（用户自答"能"）。

**完成条件（AC）**

- 用户明确相信"即使动机很低也能完成基线行为"并确认。

**保存数据**：五项评估、最弱环节、简化方式、微行为、入门步骤、基线、可选扩展。

### 4.5 第五步：找到"对"的提示（锚点匹配）

**前置**：已确定基线/微行为。

**目标**：把微行为接到稳定发生的锚点时刻。

**输入与字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 候选锚点库 | 列表 | 是 | 既有可靠事件 |
| 选定锚点 | 引用候选 | 是 | |
| 锚点最后动作 | 文本 | 是 | 锚点结束的精确时点 |
| 地点 | 文本 | 否 | 与微行为地点相容性 |
| 频率 | 枚举：每日/每周N次/不定 | 是 | 与目标频率比较 |
| 配方前两部分 | 文本 | 是 | "在我___之后，我会___" |

**交互与工具**

1. 列出一天中稳定发生的既有行为（可手动添加 + 内置锚点模板，模板含从「微习惯配方库」提取的常见锚点，如「刷完牙之后」「吃完午饭之后」）。
2. 按地点相容、频率一致、时间与情境匹配，筛选锚点。
3. 找到锚点的"最后动作"。
4. 检查锚点之后能否立刻执行微行为。
5. 生成配方前两部分。
6. 在想象中演练时间顺序。

**校验规则**

- 锚点必须来自"生活中已可靠发生的事件"；模糊锚点（"早上""有空时"）给出提示并要求改为具体事件。

**完成条件（AC）**

- 用户能清楚想象"锚点最后动作结束 → 立即开始微行为"的场景。

**保存数据**：候选锚点库、选定锚点、最后动作、地点、频率、配方前两部分。

### 4.6 第六步：庆祝成功（庆祝实验 + 配方生成）

**前置**：已确定锚点与微行为。

**目标**：找到能立即产生真实积极情绪的庆祝方式，并完成配方演练。

**输入与字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 庆祝候选 | 列表 | 是 | 试过的庆祝方式 |
| 自然度评分 | 1–5 | 是 | 每项试演后 |
| 成功感评分 | 1–5 | 是 | 每项试演后 |
| 选定庆祝方式 | 文本 | 是 | |
| 完整配方 | 文本 | 是 | 配方卡三行 |
| 演练次数 | 整数 | 是 | |
| 演练感受 | 文本 | 否 | |

**交互与工具**

1. 说明庆祝不是外部奖励，而是即时积极情绪。
2. 从内置的 100 种「庆祝方式库」浏览并选择几个可能自然的。
3. 分别当场试演，评价自然度与成功感。
4. 选定本配方庆祝方式。
5. 生成完整配方卡：

```
在我完成【锚点最后动作】之后，
我会【微行为】，
然后立即【庆祝方式】。
```

6. 连续演练"锚点 → 微行为 → 庆祝"若干次。
7. 确认并生成第一个可实践版本。

**校验规则**

- 若自然度或成功感 ≤ 2，提示继续寻找更自然的方式，但不硬阻断。

**完成条件（AC）**

- 用户已当场演练完整配方并点击"放入现实生活试验"；系统生成配方版本 v1，项目状态转为"准备实践"。

**保存数据**：试过的庆祝方式、自然度/成功感、选定方式、完整配方、演练次数与感受、配方版本号。

### 4.7 第七步：排除障碍、重复和扩展

**前置**：配方 v1 已生成。

**目标**：低负担记录现实结果，按"提示→能力→动机"诊断并调整，习惯稳定后可选生长。

#### A. 今日快速记录

默认六种结果：

```
○ 自然完成了
○ 完成了，而且自然多做了一些
○ 想起来了，但没有做
○ 完全忘记了
○ 今天没有出现锚点
○ 今天不方便记录细节
```

- 记录成功时，界面先引导用户重新感受成功（如复现庆祝），而不是立即要求填写问卷。
- 每条记录可附可选感受与情境。

#### B. 排除障碍（诊断）

诊断顺序固定为 **提示 → 能力 → 动机**。

| 现实反馈 | 优先检查 | 默认诊断 | 返回步骤 |
|---|---|---|---|
| 完全忘记 | 锚点是否可靠、明确 | 提示不明确 | 第 5 步 |
| 锚点没有出现 | 锚点频率/日程匹配 | 锚点不匹配 | 第 5 步 |
| 想起来但没做 | 时间/体力/脑力/日程最弱环节 | 能力不足 | 第 4 步 |
| 长期不想做 | 是否选错行为或愿望 | 动机/匹配问题 | 第 3 步或第 1 步 |
| 做了但庆祝别扭 | 庆祝自然度 | 庆祝不合适 | 第 6 步 |
| 配方环境变化 | 重新匹配能力与提示 | 环境变化 | 第 4 步 + 第 5 步 |

- 每次诊断只建议修改一个主要因素。
- 保存诊断记录：障碍类型、诊断路径、修改建议、用户最终决定。

#### C. 重复

- 有效配方保持不变，不做"必须升级"提示。
- 软件显示累计成功次数与配方稳定性，但**不以连续天数**作为成功指标。
- 中断后允许从原基线直接重新开始，不清零。
- 支持暂停、恢复、重新演练配方。

#### D. 扩展

仅当满足下列之一时，软件才建议扩展（且永远可选）：

- 用户经常自然多做；
- 能力明显提高；
- 用户主动提出。

扩展方向：保持原基线并稍微扩大行为 / 增加相关新微习惯 / 返回行为集群选另一个黄金行为。原微行为始终保留为状态差时的最低基线。

**完成条件（AC）**：本条为长期循环，无一次性"完成"；以"用户能持续记录、诊断、调整"为验收标准。

**保存数据**：每次实践结果、当时配方版本、可选感受/情境、障碍类型、诊断路径、修改建议与用户决定、暂停/恢复/扩展记录、自然生长行为。

## 5. 项目状态机

```
草稿 → 七步设计中 → 准备实践 → 实验中 → 稳定
  ↑                     ↓         ↓
  └────────返回修改──────┘      扩展/新增

任何状态均可：暂停 → 恢复 → 归档
```

- **草稿**：已新建，尚未进入第 1 步。
- **七步设计中**：处于第 1–6 步。
- **准备实践**：完成第 6 步、配方 v1 已生成、未开始现实试验。
- **实验中**：已记录 ≥1 条实践事件，或用户明确"开始实验"。
- **稳定**：由用户标记（或软件基于"经常自然多做"建议、用户确认）。不做自动连续打卡判定。
- 系统中**不设置"失败"状态**。

## 6. 多习惯管理与首页

- 首页列表支持按状态筛选（设计中/实践中/稳定/暂停/归档）、按愿望领域分组、搜索习惯/锚点/备注。
- 每个项目显示：下一步行动、需要处理的障碍、快速进入今日实践。
- 支持复制已有项目作为新实验起点。

## 7. 本地数据与备份需求（概要）

- 所有主要数据存入本地 SQLite（ADR-0004）。
- 数据模型详见"概念数据模型与数据库草案"（待产出），本 PRD 不再展开字段级表结构。
- 硬性要求：实践事件引用当时配方版本；每次修改记录原因（`ProjectChange`）。
- 自动滚动备份 + 手动备份 + 恢复前显示备份摘要；支持导出单个习惯与全部项目；导出优先采用可迁移、可验证的开放格式（JSON/Markdown）。

## 9. 内置参考库（只读数据源）

软件内置一批从书中附录整理出的只读参考数据，供用户在相应步骤浏览、筛选、选用。这些数据随应用打包，不写入用户本地数据库（用户选定/收藏的结果才进入 SQLite）。

| 参考库 | 内容 | 来源 | 用于 |
|---|---|---|---|
| 肯定成功方式库 | 8 种肯定框架 × 4 种反馈视角，共 32 条 | 表 9-1，PDF 第 328-329 页 | 第 6 步理解和选择更容易感受到成功的反馈方式 |
| 庆祝方式库 | 100 种庆祝方式 | PDF 第 330–335 页 | 第 6 步庆祝实验 |

| 锚点模板 | 从配方库提取的常见锚点（「刷完牙之后」「吃完午饭之后」等） | 派生自配方库 | 第 5 步锚点匹配 |

要求：
