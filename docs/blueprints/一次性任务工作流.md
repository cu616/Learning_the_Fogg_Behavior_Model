# 一次性任务工作流

- 文档版本：0.2
- 日期：2026-08-22
- 状态：第一、二层已实现；第三、四层仍为未来扩展
- 适用范围：只需完成一次、尚未形成长期重复需求的具体任务
- 相关决策：[ADR-0009：一次性任务作为七步习惯设计的补充工作流](../decisions/ADR-0009-一次性任务作为补充工作流.md)

## 1. 文档目的

现有产品以福格行为设计七步骤和长期微习惯实践为主工作流。现实中还有另一类常见需求：用户已经有一件具体事情要完成，但因为忘记、觉得困难、缺少动力或不知道如何开始而迟迟没有行动。

本工作流把书中的通用行为原理应用于一次性任务，目标不是培养自动化习惯，而是帮助**这一次具体行为越过行动线并被完成**。

书中明确说明，福格行为模型不仅适用于习惯，也能用于重大单次行为和其他行为改变（PDF 第 64–65 页）。书中还以拖延预约牙医为例，说明“入门步骤”同样能用于不需要养成习惯的一次性事情（PDF 第 124–125 页）。

## 2. 定位与边界

### 2.1 适用情况

- 预约一次就诊；
- 提交一份申请；
- 回复一封困难的邮件；
- 完成一次报销；
- 整理并发送一份材料；
- 做出一个已经明确、但迟迟没有执行的决定性动作。

### 2.2 不适用情况

- 需要长期重复并逐渐自动化的行为：进入七步习惯设计；
- 目标尚不明确、存在大量行为选择的复杂愿望：先使用行为集群和焦点地图；
- 包含多个里程碑的长期项目：应拆成项目及多个一次性任务；
- 涉及医疗、法律、财务或安全判断的任务：本流程只能帮助执行，不能替代专业判断。

### 2.3 产品关系

```text
用户想做出改变
├─ 长期重复行为 → 七步习惯设计（主工作流）
├─ 明确的一次性任务 → 一次性任务快速流程（本文）
└─ 复杂且尚未明确的愿望 → 先探索和匹配行为，再决定进入哪条路径
```

一次性任务流程是补充入口，不替代 ADR-0002 确立的七步主工作流，也不自动纳入当前 MVP。

## 3. 核心原则

1. **行为必须具体**：任务成果需要继续转换成现在或某个明确时刻能执行的动作。
2. **按 B=MAP 诊断**：行为发生需要动机、能力和提示同时具备。
3. **诊断顺序固定**：先检查提示，再检查能力，最后检查动机。
4. **优先让行为容易**：通过能力链、工具资源、缩小规模和入门步骤降低门槛。
5. **情境提示适合单次行为**：日历、计时器、摆放位置等通常比长期行动锚点更直接。
6. **完成入门步骤也是有效进展**：如果仍未完成，就继续设计下一个具体动作，不进行人格评价。
7. **不制造失败状态**：未执行是设计反馈；允许延期、取消、委托或重新协商。
8. **庆祝用于创造积极动量**：无需建立长期配方，也不默认要求重复演练。

## 4. 产品工作流分层

一次性任务功能采用四层结构。第一、二层构成默认主路径；第三、四层只在用户需要持续工作或管理有限期项目时出现。

```text
第一层：快速入口
  明确完成标准与当前下一动作
          ↓
第二层：P→A→M 诊断路由器
  识别主要阻力并跳转到对应解决方法
          ↓
第三层：行动会话（待详细梳理）
  启动、维持、分心恢复、身心恢复
          ↓
第四层：有限期项目（待详细梳理）
  多步骤、多日、检查点、临时配方
```

### 4.1 默认主路径

```text
输入任务
   ↓
明确“怎样算完成”与“现在的下一动作”
   ↓
现在能直接开始吗？
├─ 能 → 立即行动
├─ 不能或不确定 → 进入 P→A→M 诊断
└─ 打算稍后做 → 直接进入 P 提示设计
   ↓
只调整一个主要因素
   ↓
现在行动或安排到明确时刻
   ↓
完成 / 继续 / 重新诊断
```

用户不需要依次填写八个步骤。能力链、提示工具、任务价值判断和庆祝等内容只在对应分支出现。

### 4.2 两层职责边界

| 层级 | 负责解决 | 不负责解决 |
|---|---|---|
| 第一层：快速入口 | 任务捕获、完成标准、下一动作、立即/稍后选择 | 深入分析阻力、管理长时间专注、拆解完整项目 |
| 第二层：P→A→M 路由器 | 判断提示、能力或动机问题，调用对应解决工具 | 强制用户填写全部工具、直接替用户作价值决定 |
| 第三层：行动会话 | 后续梳理维持、干扰与恢复 | 当前版本暂不定义 |
| 第四层：有限期项目 | 后续梳理多步骤、多日与临时配方 | 当前版本暂不定义 |

## 5. 第一层：一次性任务快速入口

### 5.1 目标

以最低输入负担把用户的任务转成一个可以马上执行或进入诊断的具体行为。快速入口不是项目计划表，也不要求用户先完成完整的愿望澄清。

### 5.2 核心任务

1. 捕获用户原始表述；
2. 明确可观察的完成标准；
3. 明确当前唯一的下一动作；
4. 判断用户是现在行动、遇到阻力，还是计划稍后行动；
5. 将用户路由到立即执行或第二层诊断。

### 5.3 页面结构

#### 页面 A：任务捕获

默认只显示：

- **我要完成什么？**：原始任务文本；
- **怎样算完成？**：完成标准，可稍后补充；
- **现在最先做什么？**：当前下一动作。

示例：

```text
任务：完成课程大作业
完成标准：按要求上传完整文档并看到“提交成功”
当前下一动作：打开老师发来的作业要求
```

#### 页面 B：行动选择

提供三个主要操作：

- **现在就做**：进入执行确认，不强制运行诊断；
- **我卡住了**：进入第二层 P→A→M 诊断；
- **安排稍后做**：直接进入 P 分支，设计一次性提示。

辅助操作：取消、委托、延期。它们不属于失败。

### 5.4 下一动作校验

下一动作应满足：

- 是可观察动作，而非状态或成果；
- 可以在一个明确时刻开始；
- 不包含多个由“并且”“然后”连接的大步骤；
- 用户能回答“我现在是否可以直接做它”。

校验问题：

> 我现在能否直接做出这个动作，并让旁观者判断它是否发生？

如果不能，软件建议继续拆小，但不自动替用户确认。

| 仍是成果或状态 | 可执行的下一动作 |
|---|---|
| 完成报告 | 打开报告文件 |
| 进入复习状态 | 打开复习资料并阅读第一个标题 |
| 保持专注 | 完成当前题目的第一小问 |
| 处理报销 | 把三张票据放到桌面上 |

### 5.5 必填与按需字段

| 字段 | 默认要求 | 说明 |
|---|---|---|
| 原始任务 | 必填 | 保留用户原话 |
| 当前下一动作 | 必填 | 快速入口的核心输出 |
| 完成标准 | 软要求 | 简单任务可稍后补充；标记完成前必须确认 |
| 截止时间 | 按需 | 没有截止时间时不展示为错误 |
| 为什么重要 | 按需 | 仅在 M 分支或任务价值存疑时询问 |
| 完成证据 | 按需 | 需要提交、发送或审核的任务使用 |

### 5.6 第一层输出

- 一条一次性任务记录；
- 当前下一动作；
- 当前意图：现在做 / 卡住 / 稍后做；
- 下一路由：执行 / P→A→M 诊断 / P 提示设计；
- 可选的截止时间与完成标准。

### 5.7 第一层功能要求

- 支持只输入任务和下一动作就继续；
- 对模糊状态词给出具体化建议；
- 始终只突出一个“当前下一动作”；
- 允许用户手动修改软件建议；
- 自动保存原始表述和修改后的动作；
- 不要求建立行为集群、焦点地图或长期锚点；
- 不用“任务失败”“拖延者”等语言描述用户。

### 5.8 第一层验收标准

1. 用户能在一个页面内创建任务并得到当前下一动作；
2. 用户可以选择现在做、卡住或稍后做；
3. “现在做”不会被强制送入完整诊断；
4. “卡住”进入第二层诊断首页；
5. “稍后做”直接进入 P 提示设计；
6. 完成标准未填写时可以保存，但标记任务完成前会被询问；
7. 全流程离线可用并自动保存。

## 6. 第二层：P→A→M 诊断路由器

### 6.1 目标

找出当前下一动作没有发生的主要原因，只调整一个主要因素，然后尽快让用户重新行动。第二层不是完整问卷，而是按症状逐层排查和跳转的路由器。

### 6.2 诊断原则

- 默认顺序固定为 `P → A → M`；
- 不在检查提示和能力之前默认判定为动机问题；
- 每轮只选一个主要问题和一个主要调整；
- 用户可以直接选择自己确信的问题，但界面要提示推荐诊断顺序；
- 完成一次调整后返回行动，而不是继续强制检查剩余字母；
- 行动仍未发生时，才能重新进入下一轮诊断。

### 6.3 诊断首页

默认采用引导诊断，同时提供“我已经知道问题”快捷入口。

```text
一个明确而适时的提示出现了吗？
├─ 没有 / 不合适 → P 解决页
└─ 出现了，而且时机合适
   ↓
当时完成最小下一动作容易吗？
├─ 不容易 / 不清楚 → A 解决页
└─ 容易
   ↓
即使容易，你仍然不愿意做吗？
├─ 是 / 对任务有抵触 → M 解决页
└─ 否 → 立即行动
```

快捷症状映射：

| 用户反馈 | 默认路由 |
|---|---|
| 我忘记了 | P |
| 没有合适的开始时机 | P |
| 提示出现时我正在别处或没有材料 | P，并检查与 A 的匹配 |
| 我想到了，但不知道第一步是什么 | A |
| 我想到了，但觉得太难或太累 | A |
| 我完全能做，但就是不愿意 | M |
| 我不确定这件事是否值得做 | M 的任务价值分支 |
| 我已经开始但被干扰 | 暂记为第三层行动会话入口，当前文档不展开 |

### 6.4 P：提示解决页

#### 页面目标

让希望发生的任务行为得到明确、适时的提示；或削弱不希望发生的干扰行为的提示。

#### 第一个分支问题

> 你需要让哪个行为发生变化？

- **让我开始任务**：增加或修复期望行为的提示；
- **减少干扰行为**：移除、规避、忽略或重新映射干扰提示。

#### P1：为期望行为增加或修复提示

可选方法：

- 立即提示：读完引导后、短计时器响起后开始；
- 定时提示：一次性闹钟、日历或通知；
- 环境提示：把材料放到视线内、预先打开任务页面；
- 行动提示：存在可靠且相关的既有动作时，使用其最后动作；
- 修复错位提示：调整时间、地点、可见性和所需资源。

设计检查：

- 是否明确？
- 出现时用户是否在正确地点？
- 出现时用户是否有时间、工具和权限？
- 是否会被其他通知淹没？
- 任务完成后是否能关闭或移除？

配方格式：

```text
当【一次性提示】出现时，
我会【当前下一动作】。
```

#### P2：处理干扰行为的提示

按顺序提供：

1. **移除**：关闭通知、移走物品、关闭页面；
2. **规避**：改变位置、时间或设备；
3. **忽略**：仅在无法移除或规避时使用；
4. **重新映射**：让原干扰提示触发“返回任务”的动作。

界面不应只建议用户“忍住”。如果干扰仍然太容易发生，应跳转 A 页的“增加干扰难度”分支。

#### P 页输出

- 处理对象：期望行为 / 干扰行为；
- 提示问题类型：缺失 / 不明确 / 时机错位 / 情境不匹配 / 干扰提示；
- 选定方法：增加 / 调整 / 移除 / 规避 / 忽略 / 重新映射；
- 逻辑提示描述；
- 返回行动的时间与地点。

> 操作系统通知和提醒策略仍需单独 ADR。初次实现可只保存逻辑提示，由用户在外部工具中设置。

### 6.5 A：能力解决页

#### 页面目标

让期望行为更容易，或让干扰行为更难发生。

#### 第一个分支问题

> 你需要改变哪一边的难度？

- **让任务更容易开始**；
- **让干扰行为更难发生**。

#### A1：让任务更容易

按能力链检查：

`时间 → 资金 → 体力 → 脑力 → 日程`

找到最薄弱环节后，提供：

1. 提升必要技能；
2. 获取工具或资源；
3. 缩小规模；
4. 只做入门步骤；
5. 明确当前唯一的下一动作；
6. 调整发生时间或地点。

入门步骤示例：

- 只打开文件；
- 只找到电话号码；
- 只填写第一栏；
- 只把材料摆好；
- 只阅读第一条要求。

最低动机测试：

> 如果我现在很累、很忙或心情不好，这一步仍然容易做到吗？

如果答案是否定的，继续缩小或更换工具与情境。

#### A2：让干扰行为更难

反向使用能力链增加适度阻力，例如：

- 时间：增加打开干扰应用所需步骤；
- 体力：把手机或游戏设备放到需要起身才能拿到的位置；
- 脑力：退出账号、移除快捷入口；
- 日程：让娱乐设备不出现在本次工作时段；
- 工具与环境：使用专门的工作界面或移除干扰设备。

增加阻力应当安全、可逆，不使用惩罚或羞耻。

#### A 页输出

- 调整对象：期望行为 / 干扰行为；
- 能力链最弱环节；
- 采用的简化或增阻方式；
- 更新后的下一动作或环境调整；
- 最低动机测试结果；
- 立即行动或重新安排的决定。

### 6.6 M：动机解决页

#### 页面目标

在提示已经适时、行为已经足够容易的前提下，判断任务是否值得继续以及怎样处理真实的动机冲突。

#### M1：任务价值判断

依次询问：

- 这件事仍然需要完成吗？
- 它是我想做、必须做，还是可以不做？
- 应该由我完成，还是取消、委托或重新协商？
- 不做的真实影响是什么？

允许的处理决定：继续、取消、委托、延期、重新协商。任何一个决定都不标记为失败。

#### M2：处理动机冲突

如果任务仍需由用户完成，可以：

- 说明当前动作与最终成果的关系；
- 减少恐惧、厌恶、含糊和其他去激励因素；
- 重新选择一个更愿意执行的行为路径；
- 在自然出现的动机波浪中完成困难部分；
- 如果动机仍低，返回 A 页继续降低门槛。

禁止默认使用：羞耻、威胁、连续打卡清零、公开惩罚或人格评价。

#### M 页输出

- 任务处理决定；
- 主要动机冲突；
- 选定的处理方法；
- 是否返回 A 继续简化；
- 若继续执行，更新后的当前下一动作。

### 6.7 调整后的统一返回路径

P、A、M 任一页面完成后，都返回同一行动页：

```text
已调整一个主要因素
   ↓
现在就执行当前下一动作吗？
├─ 是 → 开始行动
├─ 稍后 → 保存明确提示
└─ 仍然卡住 → 开启新一轮 P→A→M 诊断
```

系统不得因为用户解决了 P 问题，就强制继续填写 A 和 M。诊断是循环路由，不是三页必填问卷。

#### 界面披露顺序

P、A、M 的解决页在同一页面内逐段展开，而不是同时展示完整字段：

```text
确认调整对象或处理决定
        ↓
选择一个主要方法
        ↓
写下这次具体怎样调整
        ↓
选择现在行动、安排稍后或再次诊断
```

- 用户未完成当前选择时，不显示下一段；
- 已形成的选择保留在上方，允许返回修改；
- “安排稍后做”已确定是任务提示路径，直接从选择开始信号进入，不再重复询问处理对象；
- 时间与地点只在所选提示方法需要时出现；时间输入只保存方案，不代表软件会自动通知；
- 最后一段是本轮调整后的行动去向，不是完成证明或评价回执。

### 6.8 第二层数据与历史

每轮诊断至少保存：

- 诊断时间；
- 当时的当前下一动作；
- 用户反馈或症状；
- 推荐路由与用户最终选择；
- 主要障碍：P / A / M；
- 采用的一个主要调整；
- 调整后的下一动作或情境；
- 结果：现在行动 / 安排稍后 / 再次诊断 / 取消 / 委托 / 延期。

同一任务可以有多轮诊断，但默认界面只显示当前有效的一轮，历史记录按需展开。

### 6.9 第二层功能要求

- 提供引导诊断和直接选择 P/A/M 两种入口；
- 引导诊断严格遵循 P→A→M；
- 每轮只突出一个主要障碍；
- P、A、M 均提供期望行为与干扰行为的对应处理；
- 完成一个分支后尽快返回行动；
- 不要求用户完成无关分支；
- 允许用户返回第一层修改下一动作；
- 诊断与调整记录可回溯；
- 全部核心建议来自本地规则与知识库，离线可用。

### 6.10 第二层验收标准

1. 用户选择“我卡住了”后进入 P 检查，而不是直接进入动机页面；
2. P 没问题时才继续检查 A，P 和 A 都没问题时才检查 M；
3. 用户可以使用“我已经知道问题”直接进入某一分支；
4. P 页能分别处理“增加任务提示”和“扫除干扰提示”；
5. A 页能分别处理“让任务容易”和“让干扰更难”；
6. M 页能支持继续、取消、委托、延期和重新协商；
7. 完成任一调整后返回行动页，不强制填写其他分支；
8. 行动仍未发生时可以开启新一轮诊断；
9. 系统不产生“失败”状态或意志力评价；
10. 每轮诊断与调整均自动保存并可回溯。

## 7. 与七步习惯设计的映射

| 七步习惯设计 | 一次性任务快速流程 |
|---|---|
| 明确长期愿望或成果 | 确认具体任务成果与完成标准 |
| 建立行为集群 | 简单任务直接确定下一动作；复杂任务可按需使用 |
| 用焦点地图选择黄金行为 | 只有存在多个可选路径时才使用简化筛选 |
| 确定长期微行为基线 | 确定当前入门步骤 |
| 优先匹配稳定行动锚点 | 优先设置适时的一次性情境提示 |
| 庆祝并演练完整配方 | 庆祝进展；通常不需要重复演练 |
| 长期记录、诊断和扩展 | 完成后关闭；未完成则继续拆解和诊断 |

## 8. 共享交互规范

### 8.1 界面语言

推荐：

- “这一步可能还不够容易，我们再缩小一些。”
- “提示可能没有在合适的时刻出现。”
- “你可以取消、委托或重新安排这件事。”
- “这次结果为下一版设计提供了信息。”

避免：

- “任务失败”；
- “你又拖延了”；
- “意志力不足”；
- 连续完成天数、清零、惩罚或羞耻性提示。

### 8.2 状态建议

```text
草稿 → 已准备 → 进行中 → 已完成
  ├────────────→ 已取消
  ├────────────→ 已委托
  └────────────→ 已延期
```

系统不设置“失败”状态。

## 9. 概念数据需求

以下概念需求已由 ADR-0014 落到 `one_time_task`、`one_time_diagnosis_round` 和 `one_time_task_event`；第三、四层后续扩展仍需另行建模：

- 任务标题；
- 任务价值与处理决定；
- 预期成果和完成标准；
- 截止时间；
- 当前下一动作；
- MAP 诊断结果；
- 诊断入口：引导诊断 / 用户直接选择；
- 调整对象：期望行为 / 干扰行为；
- 本轮主要调整及行动结果；
- 能力链最弱环节；
- 简化方式和入门步骤；
- 提示类型、时间和描述；
- 庆祝方式；
- 当前状态；
- 完成证据；
- 诊断与修改历史；
- 创建、开始、完成、取消或延期时间。

实现前需要单独确认：一次性任务是复用并泛化现有 `HabitProject`，还是建立独立实体；不得直接修改现有 14 实体模型而不记录决策。

## 10. 首版验收标准建议

未来实现一次性任务扩展时，至少应满足：

1. 用户可以通过快速入口定义成果和当前下一动作；
2. 用户可以选择现在做、卡住或安排稍后做；
3. 引导诊断按提示→能力→动机逐层路由，同时允许用户直接选择；
4. P 页可以增加任务提示或扫除干扰提示；
5. A 页可以让任务更容易或让干扰更难；
6. M 页可以处理任务价值和动机冲突；
7. 能力链、任务价值等内容仅在相关分支按需出现；
8. 每轮只调整一个主要因素，随后返回行动；
9. 用户可以完成、取消、委托或延期任务；
10. 未执行时不出现“失败”或人格评价；
11. 全流程离线可用，数据默认只保存在本地；
12. 重复性需求可以转入七步习惯设计，而不丢失原任务背景。
