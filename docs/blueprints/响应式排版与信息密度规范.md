# 响应式排版与信息密度规范

> 本文落实 ADR-0012，为首页与七步工作台提供可直接实现的排版规则。

## 首页

```text
┌──────────────────────┐  ┌──────────────────────┐
│ 习惯项目 A            │  │ 习惯项目 B            │
│ 实践中 · 当前配方      │  │ 设计中 · 第 4 步       │
│ 最近活动              │  │ 最近活动              │
│ [打开] [更多]          │  │ [打开] [更多]          │
└──────────────────────┘  └──────────────────────┘

┌──────────────────────┐  ┌──────────────────────┐
│ 习惯项目 C            │  │ 习惯项目 D            │
└──────────────────────┘  └──────────────────────┘
```

- 桌面默认一行两张卡片。
- 卡片内部主要信息上下排列，不把所有按钮挤在同一横行。
- 项目名最多显示两行；超长时截断并提供完整名称提示。
- 归档项目可以使用同一网格，不另建过长的纵向列表。

## 表单字段组

```text
┌────────────────────────┬────────────────────────┐
│ 原行为                  │ 简化后的微行为          │
│ [                    ]  │ [                    ]  │
├────────────────────────┼────────────────────────┤
│ 基线行为                │ 可选扩展                │
│ [                    ]  │ [                    ]  │
└────────────────────────┴────────────────────────┘
```

推荐组件规则：

- `.field-grid`：双列自适应栅格；
- `.field-span-2`：跨两列；
- `.field-pair`：具有明确左右关系的两个字段；
- `.optional-panel`：折叠或条件展开内容；
- textarea 默认跨两列，除非两段文本明确需要对照。

## 各步骤建议

### 第一步

- 最终愿望跨两列、独占整行。
- 可选思考记录跨两列。

### 第二步

- 行为集群画布跨两列。
- 新增行为输入与添加/收藏操作可以组成紧凑横向工具条。

### 第三步

- 焦点地图跨两列。
- 当前卡片的九级精确调整可以在地图下方两列显示“影响”和“可行性”。

### 第四步

- 能力链跨两列。
- 原行为与微行为左右对照。
- 基线行为与可选扩展左右对照。
- 技能/学习方法、工具/资源分别组成字段对。

### 第五步

- 锚点文本可以跨两列。
- 最后动作与地点并排，频率与来源/分类并排。

### 第六步

- 庆祝方式输入可以跨两列。
- 自然度与成功感并排。
- 配方预览跨两列。

### 第七步

- 结果按钮组跨两列。
- 实践感受跨两列。
- 记录历史在空间足够时可使用两列卡片；诊断详情仍独占整行。

## 响应式原则

- 宽度充足：两列字段、两列项目卡片。
- 宽度不足：自动改为单列，不出现横向滚动。
- 工作台侧栏优先折叠，保证核心输入区拥有合理宽度。
- 地图和行为集群使用自身缩放机制，不通过缩小文字强行塞入窄区域。

## 验收重点

- 桌面首页同一行能稳定显示两个项目卡片。
- 平行字段在同一视野内可比较，且没有大片无意义空白。
- 长文本仍有足够宽度，不出现拥挤或难以编辑。
- 页面长度相较当前单列版本明显缩短。
- 窄窗口自动回退后，字段顺序仍符合阅读和填写顺序。
