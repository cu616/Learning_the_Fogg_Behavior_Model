## 已实现范围

- 首页新增与长期习惯、一次性行为并列的“终止旧习惯”折叠分区，支持新建、打开、归档和带保护快照的永久删除。
- 新增独立 SQLite 实体：旧习惯项目、具体旧行为、P/A/M 对策、观察记录、替代方案。
- 改变准备支持跳过、关联已有长期习惯、自定义填写和新建长期习惯。
- 具体化页面支持概括型旧习惯、多个具体行为、典型情境、统一目标类型、聚焦与删除。
- P/A/M 工作台完整显示 3 个提示、5 个能力和 2 个动机方向；一次展开一个编辑区，每格支持多条对策、实施状态和删除。
- 首次布置清单汇总准备实施、已经设置和待观察的措施。
- 观察页保存五类快速结果、感受、新提示、未覆盖情境和调整，并能把新增调整回写到提示对策。
- 每个具体行为可由用户确认达到目标，再返回行为集群选择下一个行为。
- 替代页保存“旧提示—新行为—庆祝”、演练次数、四方向能力/动机调整，并可创建关联的七步长期习惯。
- 左侧常驻行为状态、右侧按需福格模型笔记、专业支持边界和灰玫瑰流程色已接入现有聚焦式设计系统。
- 新表纳入完整备份、全量 JSON 导入导出和 UUID/外键重映射；导出格式升级为 `fogg-lab-export-v4`，旧文件仍按缺失表兼容。

## 数据与完成语义

- 项目没有“失败”状态；观察到旧行为再次发生只增加一条现实信息。
- 观察历史、对策状态和替代演练均独立保存，不会被后一次填写覆盖。
- 完全停止、减少次数、缩短时长、降低强度和有限周期使用同一目标模型。
- “达到当前目标”由用户确认，不依据连续记录自动判断。
- 所有数据继续只保存在本机，核心工作流没有网络调用或系统通知依赖。

## 构建纠正

首次覆盖曾直接运行 `cargo build --release`，该方式没有建立 Tauri 正式发布环境，导致生成的窗口仍尝试访问开发地址 `localhost`。现已增加 `app/src-tauri/tauri.no-bundle.conf.json`，固定使用已经生成的 `dist` 本地资源，并改用 `tauri build --no-bundle` 覆盖标准 EXE。隐藏启动后通过 WebView2 本机调试信息确认实际地址为 `http://tauri.localhost/`，即 Tauri 内部离线资源协议，不依赖网络或本地服务器。
